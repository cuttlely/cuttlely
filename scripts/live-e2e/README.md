# Live pressure-test harness

These scripts drive a running Cuttlely over HTTP and the Pinecone test index. They were used for the 2026-10-04 pressure test (ETL, harness smoke, chat flow prediction API, load). They are test tools only: nothing here runs in CI, and none of it is imported by the product.

## Rules

-   Synthetic data only. Pinecone writes go only to the `cuttlely-test` index, in namespaces named `e2e-*` or `pt-*`. `lib.mjs` refuses any other host or namespace prefix for deletes.
-   Keys are never printed, logged or committed. Provider keys are read from the environment inside a subshell and stored in Cuttlely only as Cuttlely credentials. Chat flow API keys live in a chmod 600 file outside the repo (`E2E_API_KEYS`). The default directory is `$CUTTLELY_E2E_ROOT/pt-data`, or a `cuttlely-e2e` directory under the system temp dir when that variable is unset.
-   Run state, logs and evidence stay outside the repo. Set `CUTTLELY_E2E_ROOT` to choose the directory. Set `E2E_PINECONE_HOST` to the `cuttlely-test` index URL before a Pinecone call. Do not commit either value.

## Setup

1. Start Cuttlely (Postgres or SQLite) with `NODE_OPTIONS=--require=<path>/netcount.cjs` if you want outbound-call counts. The network counter is not in this folder; it logs method, host, path, status, counts and token usage, never headers or bodies.
2. Put a local admin login in a chmod 600 JSON file and point `E2E_ADMIN_FILE` at it.
3. Load keys in a subshell and create the credentials:

```bash
(set -a; . ~/.secrets/cuttlely.env; set +a; E2E_ADMIN_FILE=/path/admin.json node scripts/live-e2e/setup-credentials.mjs)
```

| `canvas-side-panel-e2e.mjs` | Headless browser check of the new card look (compact cards, settings in a side panel) on the chat flow, harness and ETL canvases: on when the browser has no choice; from classic cards, the toolbar switch makes every card narrower with exactly the same plug points and connections; a click on a card opens its fields in the panel; 20 typed characters keep the cursor; Delete in the panel keeps the card; Escape closes it; switching back shows the typed text on the classic card. On the workflow canvas, a click opens the settings in the panel instead of the dialog, and with the switch off a double click opens the dialog with the typed text. Needs no provider key. |
| `template-gallery.mjs`      | Opens every bundled canvas (Templates page files and samples) in the template preview, saves one screenshot each and an `index.html` to `GALLERY_DIR` (refused inside the repo), and fails if a card or connection is missing on screen or two cards cover each other. ## Examples

```bash
(set -a; . ~/.secrets/cuttlely.env; set +a; export E2E_ADMIN_FILE=/path/admin.json
  node scripts/live-e2e/pt-api.mjs setup
  node scripts/live-e2e/pt-api-tests.mjs auth
  node scripts/live-e2e/pt-load.mjs 300 300
  # one stage at a time, with a host-memory stop line: E2E_LEVELS=35 E2E_KINDS=rag E2E_TAG=r2 E2E_MEM_STOP_MB=2000 node scripts/live-e2e/pt-load.mjs 300 60
  node scripts/live-e2e/pt-api11.mjs
  python3 scripts/live-e2e/leak-scan.py > /tmp/leak-scan.json)

# canvas focus (no keys needed; E2E_PLAYWRIGHT points at a Playwright whose browser is installed)
E2E_ADMIN_FILE=/path/admin.json E2E_BASE_URL=http://127.0.0.1:3100 node scripts/live-e2e/canvas-focus-e2e.mjs
E2E_ADMIN_FILE=/path/admin.json E2E_BASE_URL=http://127.0.0.1:3100 node scripts/live-e2e/canvas-side-panel-e2e.mjs

# screenshot gallery of every bundled canvas (no keys needed; GALLERY_DIR must be outside the repo)
E2E_ADMIN_FILE=/path/admin.json E2E_BASE_URL=http://127.0.0.1:3100 GALLERY_DIR=/tmp/template-gallery pnpm templates:gallery
# the same gallery in the new card look, for an old-vs-new comparison
E2E_ADMIN_FILE=/path/admin.json E2E_BASE_URL=http://127.0.0.1:3100 GALLERY_LOOK=panel GALLERY_DIR=/tmp/template-gallery-new pnpm templates:gallery
# when cards cover each other: move them using the sizes that classic gallery run measured (drop --write to only list the moves)
node scripts/templates-respace.mjs /tmp/template-gallery/results.json --write

# Build with AI with a real model (OPENAI_API_KEY is stored as the "OpenAI demo" credential, never printed;
# BUILDER_OUT must be outside the repo; BUILDER_ONLY_UI=1 skips the five API builds)
E2E_ADMIN_FILE=/path/admin.json E2E_BASE_URL=http://127.0.0.1:3100 BUILDER_OUT=/tmp/builder-e2e node scripts/live-e2e/builder-e2e.mjs
```

Fault injection (failed upsert, SIGKILL after delete, slow upserts, synthetic upstream 429, broken stream) is done by flag files that the network counter reads. See the pressure-test report for the exact procedure.
