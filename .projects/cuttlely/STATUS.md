## What works on `main`

Cuttlely 1.3.2. The product version is the root `package.json`, `packages/server/package.json`, `packages/cli/package.json` and `packages/chat-widget/package.json`. The About dialog reads the server one. The root package name is `cuttlely-workspace` so the published launcher can be named `cuttlely`. The server package is `@cuttlely/server`, the UI package is `@cuttlely/ui`, and the API docs package is `@cuttlely/api-docs`.

-   **Agent teams (harnesses).** A harness is a named team: Harness Prime routes each question, specialists do the work in parallel, and Prime writes one answer. Specialists use canvas tools, retrievers, vector stores and MCP servers in process, and the agent runtime for Shell, Browser, Code execution, Files and MCP work. Any chat-model node can drive Prime or a specialist, with an optional fallback model. Turns stream over the prediction API, have a wall-clock budget, cap their context tokens, and report tokens and timings. Each harness has a run history page with a playground.
-   **Agent team delete.** Cards on the Agent Team list delete for owners and editors (`DELETE /api/v1/harnesses/:name`, 403 otherwise). A HARNESS canvas delete removes its harness record inside the chat flow delete transaction; startup removes harness records whose canvas is gone, and an orphan opens to a message instead of the run page.
-   **Analyst.** A specialist with its own isolated database (`CUTTLELY_ANALYST=auto`, or a separate Postgres URL) that creates tables, answers from real rows and pages long results. The page size is 100 rows and the statement timeout is 15 seconds unless **Admin** > **Server settings** > **Analyst** changes them (`CUTTLELY_ANALYST_ROW_CAP`, 1 to 1000; `CUTTLELY_ANALYST_STATEMENT_TIMEOUT_MS`, 1 to 120 seconds). The server clamps both. A PostgreSQL MCP node can ask for a lower cap or a shorter timeout, never a higher one. A legacy `analyst.db` is claimed by the first workspace through an exclusive link. A query step on the run card shows how many rows that query returned and a short preview of them. The preview is stored with the run trace and only includes rows that query already returned, never more than the configured row cap, and it is also capped in bytes. **Admin** > **Server settings** > **Analyst** can turn previews off (`CUTTLELY_ANALYST_TRACE_PREVIEW`). A run saved before previews still opens. On a database connected by URL (a Postgres URL credential or `CUTTLELY_POSTGRES_URL`), **Tables and views** on the PostgreSQL MCP node lists the tables, views and materialized views the login can read, views first, with a checkbox each. With any ticked, the query tool carries one line per ticked relation with its kind, up to 12 column names and its comment (D89), a `describe` tool returns one relation's columns, keys, relationships among ticked relations and view definition, and each statement is checked in its own transaction through a temporary view's query tree before it runs read only: an unticked relation, a function, operator or type outside `pg_catalog`, a denied built-in, or a statement that is not a read is refused (D87, D88). A database with a domain whose `CHECK` is volatile, not built in, denied, or uses a denied type refuses every scoped query up front, naming those domains (D88). ## How it is checked

-   `pnpm verify` on Node 24 is the merge gate (DECISIONS D27). The full run has 27 steps and ends with a timing table, slowest first. `pnpm verify --help` lists every step and the `--fast` set. The `media-size` step (also in `--fast`) fails an image or video file over 5 MB that is not in `scripts/media-size.allowlist`. The `canvas-actions` step opens the chatflow and workflow canvases in a browser, duplicates a card, deletes the copy, and closes the settings panel with the button and with Escape. It also drags a card to the top edge, and it hovers an unselected card and clicks Duplicate and Delete with the row above the card and below it. Backspace removes a selected card when the panel is closed, and Backspace in a panel field only edits that field. Backspace on a connected card marks the canvas unsaved. Deleting one of two lines from the same card clears only that line's field. A workflow mention span is removed whole, and a longer id's span stays. The saved flow for the chatflow, workflow, harness, and pipeline canvases has no dangling reference after a button delete or a keyboard delete (D60). A docs-only change uses `--fast`. The `boundaries` step fails a new import across a zone, or a new file under an inherited path that is not assigned to a subsystem. A recorded line that is no longer in the tree fails until `node scripts/check-boundaries.mjs --update` shrinks the list. The root git attributes file is in core-shared, so it is not on the inherited list. The typecheck step runs in both modes: components, the versioning core, and the server, plus `tsc --noEmit` for `packages/api-documentation`. The `versioning` step runs the versioning core tests. The `eval-routes` step (also in `--fast`) runs `scripts/eval-routes.test.cjs` in its own process and runs it once more when that process is killed by a signal.
-   `packages/components/nodes/load-coverage.test.ts` loads every catalog node and every credential class, checks the description fields, and calls `init` only when that call stays on the machine. Without coverage instrumentation, module evaluation (node and credential `require`, plus those inits) must finish in under 20 seconds. The whole test, including a cold ts-jest compile, must finish in under 150 seconds. The file's Jest timeout is 180 seconds. The `unit` step of `pnpm verify` (full and `--fast`) runs this file with `--coverage=false`, and that is the run that enforces both limits. No job in `.github/workflows/` runs it without coverage. The build job's `pnpm test:coverage` still loads every class and still fails when a problem is recorded, skips only the time assertions, and prints the elapsed time. `scripts/build-module-catalog.mjs` writes the support tier (`core`, `supported`, `legacy`, `hidden`) on each catalog row. The catalog lists 289 nodes and none is `hidden`.
-   `node scripts/health-report.mjs` prints code lines per zone, production dependencies, boundary edge counts from `scripts/check-boundaries.mjs`, and how many catalog nodes have a unit test. Node CI appends it to the build job summary, and the Docker job adds the image size (`--image cuttlely`). The report exits 0. Those CI steps do not fail the job. The 2026-10-11 figures are in [docs/reference/health-baseline.md](../../docs/reference/health-baseline.md).
-   `pnpm harness:check` (`node packages/harness/check.mjs`) and `pnpm etl:check` (`node packages/etl/check.mjs`) are offline checks with no model key and no network. `node harness/check.mjs` and `node etl/check.mjs` still run them for one release. Both include linear-time checks that feed each former slow regular expression its code-scanning input shape (about 200,000 characters) and require it to finish in under 500 ms. The harness checks also hold closing sources and numbered steps to their earlier answers: a lone `\r`, U+2028 or U+2029 does not cut a closing source, and a step indented with NBSP counts. The chat widget and server setup tests do the same for their text.
-   Analyst paging at a raised row cap is checked in `scripts/analyst-store.test.mjs`: a 600-row table with a cap of 250 is paged to the end, each row appears once, and the run card count matches the page. A full cap still allows a jump to page N. After a short page the line names the row total and says show more, with no page count, and a jump past the next page is refused. A keyset or offset result states a page count only after a length pass shows the walk matches a full cap on every page; the pass bounds text, varchar, and name by UTF-8 bytes, character(n) by the detoasted padded byte length, dates by 128 characters, and a json scalar or object by at least 24. A JSON array has no bound. A type with no bound leaves the walk unknown. Until the walk matches, a jump other than the next page or page 1 is refused. A seeded property check covers a few thousand random page sequences in buffer, keyset, and offset, including pages the budget cuts short. The same file checks that a host row cap or query timeout of 0, a negative number, or a non-numeric value uses the default and warns once, and that a query timeout under 1 second is raised to 1 second. A reused Postgres session keeps the hard-maximum client backstop, so a later longer statement is not cut by the first call's read timeout. A node row cap between 0 and 1 is 1 row. The paging phrase matcher (`show more`, `next page`, `page N`) strips trailing punctuation with a scan from the end, not a regex, and the same file checks it stays linear on a 200,000-character run of punctuation.
-   `scripts/analyst-relations.test.mjs` (in `verify-test`, and in the advisory `analyst-postgres` CI job against Postgres 14, 15, 16, 17 and 18 with `CUTTLELY_TEST_PG_REQUIRED=1`, so an unreachable service fails instead of skipping; that job also runs `packages/server/src/identity/inviteSignIn.test.ts` and `sqlStore.test.ts`, the invite-link sign-in cases on SQLite and on that Postgres) covers the table picker, including risky domains (identical text for a passing and a failing check value, and a sequence left unchanged by a `nextval` check through a user function or called directly), extension types, object-identifier types, metadata and session functions, a terminated backend, an ambiguous `describe` name and quoted column names, column names in each line and the column list on an undefined or ambiguous column error, and: listing order, enforcement (an unticked relation through a CTE, a subquery, a catalog, `information_schema`, a `regclass` literal, `query_to_xml`, `set_config`, a user function and operator, a write), paging and cursor replay under a selection, `describe` output and its sample values (only from the described ticked relation, at most 8 scope checks on one connection, and no write or `nextval` from a ticked view whose function tries both, through describe or query), an empty selection, a selection whose names are all gone, the prompt size, and the built node. The database cases use a local Postgres admin (`CUTTLELY_TEST_PG_*`, `PGPASSWORD`) and skip without one. The node case skips when the components build is older than `PostgreSQLMCP.ts`.
-   The `smoke` step boots the built server; the `upgrade` step starts it on data from an older release; the `safeboot` step checks the settings rollback.
-   The daily scheduled CI run on `main` also runs `pnpm test:queue-abort`, an end-to-end queue-mode abort test against a Redis service.
-   The required `lint` CI job runs the proprietary path check (`scripts/proprietary-paths.mjs --base HEAD^1` on a pull request) and the media size check. `pnpm verify` does not run the proprietary path check (D86).
-   CodeQL (`.github/workflows/codeql.yml`) analyzes GitHub Actions, JavaScript and TypeScript, and Python with `.github/codeql/codeql-config.yml`, which leaves out `hermes/`, the pinned upstream copy whose security releases are tracked weekly. A fourth entry (`/language:python/hermes-patches`) checks the repository out into `repo/`, copies the `hermes/` files listed in `.github/codeql/hermes-patched-files.txt` to the workspace root, and scans only that copy with `.github/codeql/codeql-hermes-patches.yml`. That list cannot go under `paths`, because the Python extractor treats each `paths` entry as a folder. `scripts/codeql-config.test.mjs` (in `verify-test`) keeps the list equal to the files `hermes/patches/` touch ([Hermes upgrades](../../docs/reference/hermes-upgrades.md#code-scanning)). The workflow pins its actions to commit SHAs, and Dependabot updates GitHub Actions weekly in one grouped pull request. Code scanning uses this advanced setup; the repository's CodeQL default setup is off. Every open result outside `hermes/` that had a cheap fix is fixed; the rest are false positives, by-design behavior, test-only code, or upstream Hermes code, each with a dismissal reason in [#206](https://github.com/cuttlely/cuttlely/pull/206). Dismissing them is a maintainer action in the Security tab.
-   Workflows in `.github/workflows/` are the CI definition, but they are not the merge gate. See [OPEN.md](./OPEN.md). Their `pnpm/action-setup` steps take the pnpm version from `packageManager` in `package.json`; a separate `version` input stops the step when the two disagree.
-   The server's sanitize-html is 2.18.1 (lockfile), which closes the low-severity GHSA-374f-7chj-9948.
-   `pnpm audit --prod` and `pnpm audit` report no critical advisory. Three high ones are left, and none has a fixed release. `extract-zip` (two advisories) is in Puppeteer's browser download, which Cuttlely skips (`PUPPETEER_SKIP_DOWNLOAD`), so that code does not run. `braces` 3.0.3 is the latest release and is still in the vulnerable range; it arrives through the command-line file matcher and through dev tooling, and request handling does not pass input to it. `expr-eval` is not installed: the older community package that depended on it is gone, and that package has no fixed release.
-   A green `pnpm verify` is not a real-model run. Harness and analyst behaviour that depends on a model needs a live run with a real credential before it is called done (MEMORY).
