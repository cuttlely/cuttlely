# Status

Last refreshed 2026-10-13. Check `git log origin/main` for anything newer.

## What works on `main`

Cuttlely 1.0.2. The product version is the root `package.json`, `packages/server/package.json`, `packages/cli/package.json` and `packages/chat-widget/package.json`. The About dialog reads the server one. The root package name is `cuttlely-workspace` so the published launcher can be named `cuttlely`. The server package is `@cuttlely/server`, the UI package is `@cuttlely/ui`, and the API docs package is `@cuttlely/api-docs`.

-   **Agent teams (harnesses).** A harness is a named team: Harness Prime routes each question, specialists do the work in parallel, and Prime writes one answer. Specialists use canvas tools, retrievers, vector stores and MCP servers in process, and the agent runtime for Shell, Browser, Code execution, Files and MCP work. Any chat-model node can drive Prime or a specialist, with an optional fallback model. Turns stream over the prediction API, have a wall-clock budget, cap their context tokens, and report tokens and timings. Each harness has a run history page with a playground.
-   **Analyst.** A specialist with its own isolated database (`CUTTLELY_ANALYST=auto`, or a separate Postgres URL) that creates tables, answers from real rows and pages long results. The page size is 100 rows and the statement timeout is 15 seconds unless **Admin** > **Server settings** > **Analyst** changes them (`CUTTLELY_ANALYST_ROW_CAP`, 1 to 1000; `CUTTLELY_ANALYST_STATEMENT_TIMEOUT_MS`, 1 to 120 seconds). The server clamps both. A PostgreSQL MCP node can ask for a lower cap or a shorter timeout, never a higher one. A legacy `analyst.db` is claimed by the first workspace through an exclusive link.
-   **Knowledge pipelines (ETL).** A pipeline canvas with streaming sources, incremental upsert into any vector store, every text splitter and embeddings node, schedules, run history, and the ETL Retriever for chatflows and harnesses.
-   **Chatflows and agentflows.** The visual canvas and node catalog, with Build with AI on every canvas. Older V1 agentflows still run but are not offered for new work. Optional node packs load from `CUTTLELY_NODE_PACKS` (a directory or a package whose `package.json` declares `cuttlely.nodePack`). The packs that ship with the install always load. Today that is `@cuttlely/node-pack-vector-stores` (vector store nodes, the credentials only they use, and the dependencies only they import), `@cuttlely/node-pack-tools-mcp` (tool nodes that call an outside service, the prebuilt MCP server nodes for those services, and the credentials and dependencies only those nodes use), `@cuttlely/node-pack-caches-memory` (cache nodes and memory backends that use an outside service, the credentials only they use, and the dependencies only they import), and `@cuttlely/node-pack-legacy-chains` (completion model nodes, the chain nodes that carry the DEPRECATING badge, the credential only those nodes use, and the dependencies only they import). Custom Tool, Custom MCP, chatflow and agentflow tools, Retriever Tool, Calculator, Request tools, the ETL Retriever, and the PostgreSQL MCP node the analyst uses stay in `packages/components`. Buffer Memory, Buffer Window Memory, Conversation Summary Memory, Conversation Summary Buffer Memory and the agent memory nodes stay there too. `CUTTLELY_NODE_PACKS` adds packs on top. A blank value adds nothing. `INCLUDE_NODE_PACKS=0` skips the shipped packs. A saved flow that uses a node that is not installed opens with a placeholder card that names the pack and keeps the lines into that card, export leaves that node's data as saved, and a prediction returns 422 with a plain message. When the saved node has no `nodePack`, the card and the 422 use `packages/server/src/utils/node-pack-index.json` (node name and label to package name), generated by `scripts/build-node-pack-index.mjs` from `packages/node-pack-*/nodes`. The server build and the image build check that committed file and copy it into `dist` before a slim image leaves the packs out. They do not rewrite it. `GET /api/v1/nodes/pack-index` returns that list. A save or an import writes `nodePack` from the index when the field is absent (D54). [Optional node packs](../../docs/how-to/node-packs.md).
-   **Drafts and version history.** Chatflow, agentflow, and harness canvases save to a draft; Publish makes that draft Live, and Roll back sets Live to an earlier version. The harness canvas chat and Try it run the draft when one exists, including its specialists, tools, and models. A draft try uses its own gateway token and a marked try profile, so a published run stays on the saved harness while the try is in flight. SQL tools refused on a try stay on that try's profile, and the analyst page stays on the saved harness. A harness cannot be saved or imported under a name that matches a try profile. A specialist profile id that would pass 64 characters keeps a short hash of the full name; an id that already fits is left as it is. When the harness name itself leaves no room, that profile is `tryx` plus 16 hex and is removed by its parent marker when the specialist goes away. A canvas try is closed before its directory is removed. Startup removes a try left behind by a crash, token included, only when that directory carries the try marker and it is not a saved harness. An in-flight try keeps a lock file in its directory, tied to that process, so another process does not remove it while the same process is still running. A specialist directory left after its try directory is gone is removed on the next start, and its token is not loaded. `POST /api/v1/harnesses/:name/runs` keeps serving the published roster until Publish. ETL pipelines still save straight to Live. Restore, a check that replays a chosen number of recent real questions before Publish (4, 10, 25, 50, or 100; 4 by default; chatflows and agentflows) or the rows of a saved dataset scored with selected evaluators, and the same check for an agentflow that starts from a form, a webhook or a schedule, replaying that many distinct recorded inputs from recent executions and showing where each one came from and when it was recorded (the box is titled Check recent runs from the canvas before the check request returns; with none, the dialog says how to create a run; when fewer runs exist than the choice, the picker is labeled Requested runs; a dataset check on that start is refused), an optional copy in GitHub, promotion along an ordered list of environments, and Dev to Prod promotion. Promote runs that check on the receiving server against that server's own questions or executions. A saved Dev or Prod label is still dev then prod. Promotion moves only to the next environment, and each hop keeps the behavior check and the credential-name check (D57). On a longer list, the review page for one flow shows the version each environment has of it. The check column stays From Dev on the saved pair and names the previous environment otherwise. Each server stores the list. A publisher records a fingerprint of it with the copy, and that copy is not finished until the fingerprint is recorded. A reader offers new versions only when the fingerprint matches. Once any fingerprint is recorded, a different list or a version with no fingerprint is not offered. The only read that still accepts versions with no fingerprint is the saved Dev and Prod pair, when the repository has no fingerprint record at all. A named list installs a tip only when the note on it matches. A named Prod whose record is missing keeps the versions already offered and offers nothing new. A list change that keeps what this server reads and copies rewrites that fingerprint on the versions already copied. A named list with no environment chosen does not count versions as waiting, and connect is refused until one is chosen. A later environment cannot connect unless the previous branch's tip carries this server's recorded list, so a README-only branch, a note on another commit, or a different list is refused and nothing is saved or copied. The check and that first copy use the same list. An environment-only save does not repair a list that cannot be read. A connection file that cannot be read is reported separately, so the card and the promote page keep the saved list. Saving the saved pair does not replace a named list that still parses. `cuttlely check` runs that check from a pipeline and exits 1 when `--fail-on-changed` sees a Changed answer. [Fail a build when answers change](../../docs/how-to/ci-gate.md).
-   **Share and embed.** The `@cuttlely/chat` widget, served by the server at `/embed/chat.js`, for share links and website embeds, including charts on cross-site embeds that the chatflow allows.
-   **API.** Chatflows, agentflows and harnesses through `POST /api/v1/prediction/:id`, with document uploads, streaming, caller-owned sessions and hashed API keys. `docs/api.md` and `examples/web-app/` show a real app.
-   **Token totals over time.** A finished chatflow, agentflow, Multi Agents canvas, Sequential Agents canvas, or harness run adds its input and output tokens to `token_usage_day`, keyed by workspace, flow, model, and UTC day. A chatflow whose only node is a harness stores the team's tokens on the chatflow. A Tool Agent that calls the harness tool records that same payload on the chatflow, because the tool text has no counts. The harness model calls are not also added by the chatflow counter. A harness run started from the harness API, and a harness canvas draft try, stores them under the harness name. The draft try is the same write as the public run, once. An ordinary chatflow, and a Multi Agents or Sequential Agents canvas, record the token counts the model calls already reported. An Agent step that calls tools stores the sum of each model call, including calls from before a tool approval, a structured-output conversion, and a memory summary. The step cost and the execution chip's token total use that same sum. A loop that finishes a pass and later stops for approval keeps the finished pass. A Sequential Agents interrupt saves the waiting action on the chat message before that action is streamed, and writes the daily total when the run finishes. A resume reads that saved action and ignores usage sent on the request. An action with no saved id fails the resume and writes no partial total. An agentflow Agent that calls a harness records that harness payload on the agentflow together with the Agent's own calls. `GET /api/v1/stats/usage` returns the daily totals and the totals per flow for 7, 30, or 90 days (`days`, or `range` as `7d`, `30d`, or `90d`), or a custom range, filtered by flow and model. `range` cannot be combined with `days` or a start or end date. The caller needs `chatflows:view` or `agentflows:view`, and so does `GET /api/v1/stats/:id`. A failed write does not change the run. A publish check counts toward the total. Prices and a usage page are not part of this. [Usage API](../../docs/reference/usage-api.md).
-   **Datasets, evaluators, and evaluations.** The sidebar opens Datasets, Evaluators, and Evaluations (D55). A dataset is example rows, an evaluator is a check, and an evaluation runs a dataset against a chatflow or agentflow. The organization owner can use them, and a role can be granted `datasets:*`, `evaluators:*`, or `evaluations:*`. The flow picker requests only the chatflows and agentflows that role can view. Custom assistants are not evaluated. Deleting rows stays inside the caller's workspace. A grading credential on a new evaluation must be owned by the team. A flow run, including history load and clearing a session, can decrypt a credential that team owns or that was shared into it. A run calls the prediction route on this server when `APP_URL` is unset. A create with a missing dataset, a bad flow list, no flow, an unknown flow, a flow from another team, or a missing name is rejected before a row is saved. A flow list sent as a JSON array is stored as that same JSON string. The evaluation pages do not start that check. A dataset can drive the check in the Publish dialog, which scores each answer with the selected evaluators and shows a pass rate per side. Reading that check returns the row inputs, expected outputs, and evaluator names only to a caller who can view them. [Evaluations](../../docs/how-to/evaluations.md).
-   **Sign-in and teams.** WorkOS AuthKit sign-in or one local account, teams, users and roles in the app database, and workspace scoping on every route. [Roles and permissions](../../docs/how-to/roles-and-permissions.md) lists every permission key and the pages and API routes that check it. Publish, draft Save, Review, and Discard draft check `chatflows:update` on `/canvas`, `/harnesscanvas`, and `/etlcanvas`, and `agentflows:update` on the agentflow canvas. The first save of a new flow checks create. Edit Name checks create or update. Use Template needs `templates:marketplace` or `templates:custom` to open the template, and then `agentflows:create` on an agentflow template or `chatflows:create` on a chatflow, harness, or ETL template. `scripts/permission-keys.test.mjs` fails when that table and the keys in the server and the UI differ, or when a permission literal is not in the catalog.
-   **Run traces.** Optional OpenTelemetry traces for chatflow predictions and agentflow runs (`CUTTLELY_OTEL_TRACES`, off by default). One span for the run, a child span per node, and child spans for model and tool calls, with flow id, node type, model name, and token counts. Question and answer text stay off the span unless `CUTTLELY_OTEL_TRACES_CONTENT` is on. The exporter sends only spans started for that run, not spans from the process-wide tracer. Harness runs are not traced yet. [Run traces](../../docs/how-to/observability.md).
-   **Admin panel.** Admin > Server settings holds every server setting with help text, a review step, restart to apply, safe boot back to the last good settings, History, and a guided sign-in setup. Admin > Logs shows recent server log files from `LOG_PATH` for the organization owner or a role with `logs:view`, with level and time filters. Presets send a range token the server expands on its own clock. Custom sends the browser's `YYYY-MM-DD-HH` stamps, which the server reads as its own local hours. The page returns one contiguous recent section: a newer file that was read in full can be followed by the next older file, and once a file is tailed, older files are not added. Redaction runs on the joined text, so a secret that spans lines becomes `[secret hidden]`. A capped tail keeps lines only from the first log record (`YYYY-MM-DD HH:mm:ss [LEVEL]:`, and an error record is a record start). Lines before that record, including a window with no record start, are replaced with `[earlier output cut]`. An API key cannot read them. Login activity stays closed (D56). `CUTTLELY_SECRETKEY_OVERWRITE`, `CUTTLELY_FILE_SIZE_LIMIT` and `DISABLE_CUTTLELY_TELEMETRY` are compatibility aliases for the existing variables. When both names are set, the `CUTTLELY_` name is used, except the encryption key: different values refuse to start. `METRICS_PREFIX` is optional and unset output matches the metric names published before it.
-   **First ten minutes.** Install, first account, and Try the demo, which opens a made-up customer care team on the person's own model key with its chat open: a customer specialist (support desk database), an operations specialist (warehouse and carrier scans) and a policy specialist (the written Service Recovery Policy and its remedy table, sent after operations), each in its own folder with its own data and Python tools, with Harness Prime writing the decision, the reply, the actions and the evidence. The data and tools are in `samples/demo/customer-care`. The bakery team is the quickstart on the same card. The README section "Your first 10 minutes" walks through it.
-   **Install and deploy.** Docker Compose (SQLite, one container), `npx cuttlely` (the same image, through the `cuttlely` launcher), from source, and a Render Blueprint (Docker web service, Postgres, disk). The server serves the built UI from `packages/server/dist/ui`, falling back to a newer `packages/ui/build` or a linked UI package. A production install does not install the UI package's libraries. `pnpm dev` still serves the UI on port 8080. The image includes Chromium and the IP geolocation database. `INCLUDE_BROWSER=0` builds one without Chromium; Puppeteer and Playwright document loaders in that image fail with `this image has no browser`. The agent runtime's browser tool also cannot browse there: it returns success: false, and the server keeps running. `CUTTLELY_OMIT_GEOIP=true` leaves the geolocation database out; audit events then have no country and no region. The two arguments are independent, the defaults keep both, and the published image is still the default build. `INCLUDE_NODE_PACKS=0` leaves optional node packs out of the image (`/etc/cuttlely/no-node-packs`); the default `1` keeps them, including the vector store pack, the tools and MCP pack, the caches and memory pack, and the legacy completion and chain pack. It is independent of the browser and geolocation arguments. `docs/how-to/from-source.md` covers the dev server, the tests and `pnpm verify`. `@cuttlely/chat` is the embeddable chat widget, also served by the server at `/embed/chat.js`.
-   **Releases.** `pnpm release` cuts a release from a clean `main`, drafts by default, and pushes the image or publishes the GitHub release only on a flag. `pnpm release X.Y.Z --npm` publishes the npm packages from that annotated tag after the image and the GitHub release are public. v1.0.2 (the dependency security release) is the latest release: the tag, the published GitHub release, the image `ghcr.io/cuttlely/cuttlely` at `1.0.2` and `latest`, and `cuttlely` and `@cuttlely/chat` 1.0.2 on npm all come from that tag. `CHANGELOG.md` dates it 2026-10-11. The npm 1.0.0 packages were built from a commit after the v1.0.0 tag and are deprecated in favor of 1.0.1. The full `pnpm verify` tests upgrades from a fixture made from the v1.0.2 tag.
-   **Graceful shutdown.** On SIGTERM or SIGINT the server stops taking new requests (`503` with `Retry-After`) and lets running answers and streams finish for up to 25 seconds (`CUTTLELY_DRAIN_TIMEOUT_MS`). The Compose files give the container 35 seconds to stop.
-   **File links in Agent answers.** A file an Agent card links in its answer opens for 15 minutes without the flow's API key: the link carries an expiry and an HMAC over the organization, flow, chat and file name, keyed from the server's own secret. A changed or expired link falls back to the key or session checks.
-   **Provider rate limits.** Chat models and LLMs make at most 3 tries and start no new try after 20 seconds. A provider that keeps answering 429 is reported as `429` with `Retry-After` (the provider's wait, else 30 seconds), and a stream ends with an `error` event carrying `status`, `code` `RATE_LIMITED` and `retryAfter`. An out-of-credit 429 still fails as `500`.
-   **No call home.** A default install reaches only services an operator or a flow set up. `SECURITY.md` lists every outbound host and how to turn it off.
-   **Website product videos.** Each card under "Tools your teams use" on the home page has a short video of a real recording: a poster first, a muted loop that plays only while the card is on screen, and a narrated version with captions in a dialog. Nothing autoplays with reduced motion, on small screens, or when `navigator.connection.saveData` is set. A Save-Data request header alone does not opt out, because the site is static. The hero video follows the same rule. The hero and the tile loops start downloading when they are within about a viewport of the screen, two at a time and in page order. A loop that is already half on screen moves ahead of the ones that are only nearby, and it plays when its download starts, still with at most two downloads in flight. A loop that has already fetched is not loaded again, so playback is not sent back to the start. A slot is freed when the loop can play through, when the video reports an error, when the last candidate fails, or when the element is already out of sources or fully buffered as the slot opens. A download that only stalls keeps its slot. A frozen page aborts the fetch without those events. Once the page is visible again, every held loop that is not yet fully buffered is loaded again, whether it was playing or had scrolled off screen, and the playhead is put back once that time is seekable, retrying a seek that did not stick. A second freeze before that seek has landed keeps the original time. A playhead the visitor has moved since the reload is left alone, including a seek back to the start. A second freeze before the first metadata event does not add another listener. Once that metadata arrives, a restore that started at the beginning is finished, and a later freeze reads the playhead as it is. A fully buffered loop is left as it is. Safari and Firefox do not fire resume, so a socket aborted while hidden, and not restored from the back-forward cache, is restarted only when that hidden resume was already seen and the page becomes visible later. Returning to a visible tab does not restart a download on its own, because that would abort one that is still healthy. The narrated video in a dialog starts downloading when the pointer or keyboard reaches its button, and it does not play until that button is used. Homepage video and poster addresses include a short content hash of the file. The files are in `website/public/media/products/`. The muted loop is the caption-free recording; only its closing card differs. Each closing card states three figures, each with a plain caption, on one shared baseline. It does not state a price. The chatflow and share cards use a median of 20 measured runs of the recorded flow and questions. The agentflow card uses a median of 20 runs of an equivalent flow with the same branches and questions, not the recorded canvas. The table is in `.projects/cuttlely/video-card-latency.md`. Those recordings play the model waits faster than real time. The other three cards use a figure the product shows. The three numbers on a card are the same weight and share one baseline. The frames before the card match the recording.
-   **Website one real run.** On the home page, the "Not the obvious answer" section shows the quote and the twist, and the specialist cards and the decision fold under a "See how the agent team worked it out" toggle (a native `<details>`, so it works without JavaScript). A "Read how harnesses work" link sits beside it.
-   **Website screenshots.** On the project site, a content screenshot opens full screen. Visitors can zoom and pan it, and close it from the button, the Escape key, the backdrop or the browser back button. Logos, icons and the mascot stay as they are.

## How it is checked

-   `pnpm verify` on Node 24 is the merge gate (DECISIONS D27). The full run has 24 steps. `pnpm verify --help` lists every step and the `--fast` set. A docs-only change uses `--fast`. The `boundaries` step fails a new import across a zone, or a new file under an inherited path that is not assigned to a subsystem. A recorded line that is no longer in the tree fails until `node scripts/check-boundaries.mjs --update` shrinks the list. The typecheck step runs in both modes: components, the versioning core, and the server, plus `tsc --noEmit` for `packages/api-documentation`. The `versioning` step runs the versioning core tests.
-   `packages/components/nodes/load-coverage.test.ts` loads every catalog node and every credential class, checks the description fields, and calls `init` only when that call stays on the machine. Without coverage instrumentation, module evaluation (node and credential `require`, plus those inits) must finish in under 20 seconds. The whole test, including a cold ts-jest compile, must finish in under 150 seconds. The file's Jest timeout is 180 seconds. The `unit` step of `pnpm verify` (full and `--fast`) runs this file with `--coverage=false`, and that is the run that enforces both limits. No job in `.github/workflows/` runs it without coverage. The build job's `pnpm test:coverage` still loads every class and still fails when a problem is recorded, skips only the time assertions, and prints the elapsed time. `scripts/build-module-catalog.mjs` writes the support tier (`core`, `supported`, `legacy`, `hidden`) on each catalog row.
-   `node scripts/health-report.mjs` prints code lines per zone, production dependencies, boundary edge counts from `scripts/check-boundaries.mjs`, and how many catalog nodes have a unit test. Node CI appends it to the build job summary, and the Docker job adds the image size (`--image cuttlely`). The report exits 0. Those CI steps do not fail the job. The 2026-10-11 figures are in [docs/reference/health-baseline.md](../../docs/reference/health-baseline.md).
-   `pnpm harness:check` (`node packages/harness/check.mjs`) and `pnpm etl:check` (`node packages/etl/check.mjs`) are offline checks with no model key and no network. `node harness/check.mjs` and `node etl/check.mjs` still run them for one release.
-   Analyst paging at a raised row cap is checked in `scripts/analyst-store.test.mjs`: a 600-row table with a cap of 250 is paged to the end, each row appears once, and the run card count matches the page. A full cap still allows a jump to page N. After a short page the line names the row total and says show more, with no page count, and a jump past the next page is refused. A keyset or offset result states a page count only after a length pass shows the walk matches a full cap on every page; the pass bounds text, varchar, and name by UTF-8 bytes, character(n) by the detoasted padded byte length, dates by 128 characters, and a json scalar or object by at least 24. A JSON array has no bound. A type with no bound leaves the walk unknown. Until the walk matches, a jump other than the next page or page 1 is refused. A seeded property check covers a few thousand random page sequences in buffer, keyset, and offset, including pages the budget cuts short. The same file checks that a host row cap or query timeout of 0, a negative number, or a non-numeric value uses the default and warns once, and that a query timeout under 1 second is raised to 1 second. A reused Postgres session keeps the hard-maximum client backstop, so a later longer statement is not cut by the first call's read timeout. A node row cap between 0 and 1 is 1 row.
-   The `smoke` step boots the built server; the `upgrade` step starts it on data from an older release; the `safeboot` step checks the settings rollback.
-   The daily scheduled CI run on `main` also runs `pnpm test:queue-abort`, an end-to-end queue-mode abort test against a Redis service.
-   Workflows in `.github/workflows/` are the CI definition, but they are not the merge gate. See [OPEN.md](./OPEN.md). Their `pnpm/action-setup` steps take the pnpm version from `packageManager` in `package.json`; a separate `version` input stops the step when the two disagree.
-   `pnpm audit --prod` and `pnpm audit` report no critical advisory. Three high ones are left, and none has a fixed release. `extract-zip` (two advisories) is in Puppeteer's browser download, which Cuttlely skips (`PUPPETEER_SKIP_DOWNLOAD`), so that code does not run. `braces` 3.0.3 is the latest release and is still in the vulnerable range; it arrives through the command-line file matcher and through dev tooling, and request handling does not pass input to it. `expr-eval` is not installed: the older community package that depended on it is gone, and that package has no fixed release.
-   A green `pnpm verify` is not a real-model run. Harness and analyst behaviour that depends on a model needs a live run with a real credential before it is called done (MEMORY).
