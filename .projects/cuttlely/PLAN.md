## Kraken 2.0 development

The `Kraken` branch tracks the [native runtime proposal](https://github.com/cuttlely/cuttlely/issues/594). For an isolated canary, set `CUTTLELY_NATIVE_PRIME_TEAMS` to a comma-separated list of exact saved team names on every process that admits turns. Agent-mode Prime can delegate to a model-only or plain Calculator specialist with saved canvas playbooks. The specialist can list its assigned playbooks and read their Markdown. The specialist context budget applies to the complete tool exchange, including the playbook text. A team with other capabilities receives `native_unsupported`.

Queued agent turns record their engine at admission. Workers honor that choice across configuration changes. Older job rows without an engine use the bundled runtime. To roll back new admissions, remove the team name and restart the admitting processes. Keep both runtimes available until queued and running work drains. A completed agent trace identifies its engine and the native specialist tools it used.

`pnpm harness:check` includes the saved Calculator canvas, scoped playbook lookup, delegation and cancellation. Full verification runs `scripts/kraken-upgrade.test.mjs` against PostgreSQL. Separate server boots and external workers with opposite canary settings verify the saved flow, credential, tool trace and chat through native cutover, empty disk and rollback. Provider and legacy runtime replies are simulated. The same suite uses the installed MCP client to initialize the saved Ops example, list and call its allowed tool, and check rejection of an unknown tool. The example accepts newline-delimited JSON and legacy Content-Length messages.

Native MCP and Analyst, shell/code and browser execution, operator files outside saved canvas playbooks, artifact continuity, and a Hermes-free distribution remain release work.

## Next concrete tasks

PostgreSQL application storage includes the verified SQLite primary copy, ETL and vector stores, agent teams, settings and credentials, uploads, and current and historical flow versions. The [operator guide](../../docs/how-to/postgres-side-stores.md) covers fresh installs, existing PostgreSQL installs, SQLite migration, optional S3-compatible file storage, host-file dependencies and rollback. [PostgreSQL consolidation #516](https://github.com/cuttlely/cuttlely/issues/516)

The full release gate runs the primary copy, side-store migration and replacement fixtures in its `storage-recovery` step. The [empty-disk regression](../../scripts/storage-replacement.test.mjs) passed locally and on a disposable hosted service for fresh PostgreSQL, existing PostgreSQL and migrated SQLite installations. Each replacement signed in, ran a prediction using a synthetic model, and used a saved credential and an attachment from a separate worker process. The operator storage test writes, reads and removes a file on the active PostgreSQL backend. The replacement fixture exercises that API on all three installation paths. The S3-compatible upload and read checks used a local endpoint. The [storage scope tests](../../packages/components/src/storage/fileStorageTraversal.test.ts) cover rejection of an all-slash folder before contacting S3 and preservation of repeated separators inside an object key. The [migration tests](../../packages/etl/check/upgrade-control.test.mjs) also cover a missing object, a digest mismatch and a changed bucket.

The server and workers verify the storage selection before writing application data. When a legacy installation cannot reach its host database at startup, the health endpoint returns HTTP 503 and identifies the outage. The [safe boot check](../../scripts/safeboot-check.mjs) covers that recovery path.

The storage upgrade includes regular local profile prompts in its verified PostgreSQL snapshot. Each new runtime disk restores that snapshot once. Later prompt edits remain local.

The post-1.7.15 skill preflight compares runtime files with the catalog produced by a clean skill sync during installation. Exact matches and the two rebuildable skill metadata files appear as temporary. The storage recovery suite covers changed, custom and linked files, profiles that opt out of bundled skills, and missing catalog entries.

The [disk storage inventory](../../docs/reference/disk-storage-inventory.md) maps application, workflow and runtime SQLite files, server settings and credentials to their writers and retention requirements. Compare a private metadata inventory before and after each overall upgrade test. The ETL store gate queues already-admitted writes before draining and allows subsequent calls after a failed statement. A regression covers both behaviors.

-   **Resilient save queue (done).** Landed on main as `52e29426` ([#462](https://github.com/cuttlely/cuttlely/pull/462)) from `fix/save-queue`. It shares a single-flight queue between both canvases. Draft writes replay only after a missing response and a status check; HTTP write responses never replay. Landed detection requires present draft metadata, a changed hash, the current account, an updated time between the first send minus two minutes and the last settle plus two minutes, and equal content for non-file canvases. Later recovery requires the captured draft base to remain unchanged. Non-file bursts continue through no-response reads; file canvases and HTTP read errors wait. Live writes reconcile parsed canvas, name, file names, and update time; a guarded action sends at most one PUT. Confirmed older writes run before a newer pending snapshot. Creation uses one POST, waits for a known save mode, and turns a later queued Save into a draft or Live update on the returned id; an unavailable post-create status read gets its own Retry notice. Internal name and starter-question updates stay serialized without replacing a user snapshot or clearing first-save questions early. An unanswered inline name remains available to the next canvas Save. Busy state holds inline name Save and Publish until the queue is idle. Session refresh is single-attempt and does not reissue writes. The optional `Idempotency-Key` header and `expectedUpdatedDate` comparison remain deferred.
