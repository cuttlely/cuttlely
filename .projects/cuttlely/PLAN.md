-   **Resilient save queue (done).** Landed on main as `52e29426` ([#462](https://github.com/cuttlely/cuttlely/pull/462)) from `fix/save-queue`. It shares a single-flight queue between both canvases. Draft writes replay only after a missing response and a status check; HTTP write responses never replay. Landed detection requires present draft metadata, a changed hash, the current account, an updated time between the first send minus two minutes and the last settle plus two minutes, and equal content for non-file canvases. Later recovery requires the captured draft base to remain unchanged. Non-file bursts continue through no-response reads; file canvases and HTTP read errors wait. Live writes reconcile parsed canvas, name, file names, and update time; a guarded action sends at most one PUT. Confirmed older writes run before a newer pending snapshot. Creation uses one POST, waits for a known save mode, and turns a later queued Save into a draft or Live update on the returned id; an unavailable post-create status read gets its own Retry notice. Internal name and starter-question updates stay serialized without replacing a user snapshot or clearing first-save questions early. An unanswered inline name remains available to the next canvas Save. Busy state holds inline name Save and Publish until the queue is idle. Session refresh is single-attempt and does not reissue writes. The optional `Idempotency-Key` header and `expectedUpdatedDate` comparison remain deferred.

Importing a saved chatflow keeps an edge that still points at the same input when only the handle type name changed. The shipped Bakery helper example keeps the ChatOpenAI to Conversation Chain connection.
