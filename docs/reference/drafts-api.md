# Drafts API

These routes keep a flow's canvas edits in a **draft** and put them **Live** with **Publish**. Live is what the prediction API, embeds, shared links, MCP, schedules and webhooks run. The draft is what the canvas and its test chat show. How drafts look in the app: [Drafts and Publish](../how-to/versioning.md#drafts-and-publish). History of each Publish and Roll back: [History API](./versioning-api.md).

Drafts are on by default. `CUTTLELY_DRAFTS=off` (also `false`, `0`, or `no`) turns them off; any other value, or no value, leaves them on. See [History settings](./versioning-settings.md#cuttlely_drafts). With drafts off, every route below except `GET` refuses with 409 `Drafts are off on this server.`, and the canvas saves straight to Live.

All routes are under `/api/v1/flow-drafts`. A signed-in session works, and so does an API key with the permissions below. The flow must be in the caller's active workspace; any other flow id returns 404. The route lets in a caller with `chatflows:*` or `agentflows:*` for that action, and then checks the permission for the flow's own type. A chatflow, a harness, a pipeline, and a flow with no stored type use `chatflows:*`. An agentflow and a legacy multi-agent canvas use `agentflows:*`. An assistant uses `assistants:*`, and the route gate above still applies, so an assistant-only key is refused before that check. Without the type's key the route returns 403.

| Method   | Route                         | Permission                                |
| -------- | ----------------------------- | ----------------------------------------- |
| `GET`    | `/:chatflowId`                | `chatflows:view` or `agentflows:view`     |
| `PUT`    | `/:chatflowId`                | `chatflows:update` or `agentflows:update` |
| `DELETE` | `/:chatflowId`                | `chatflows:update` or `agentflows:update` |
| `PUT`    | `/:chatflowId/settings`       | `chatflows:update` or `agentflows:update` |
| `POST`   | `/:chatflowId/publish`        | `chatflows:update` or `agentflows:update` |
| `POST`   | `/:chatflowId/rollback`       | `chatflows:update` or `agentflows:update` |
| `GET`    | `/:chatflowId/check`          | `chatflows:view` or `agentflows:view`     |
| `POST`   | `/:chatflowId/check`          | `chatflows:update` or `agentflows:update` |
| `GET`    | `/:chatflowId/check/:checkId` | `chatflows:view` or `agentflows:view`     |
| `DELETE` | `/:chatflowId/check/:checkId` | `chatflows:update` or `agentflows:update` |

## Kinds on these routes

Every route in the table above is registered for any flow id. What it does depends on the stored type.

| Stored type            | Kind                                                          | Type permission                                                | Draft routes                                                                                                                    | Check routes                                                                                                                                                                                      |
| ---------------------- | ------------------------------------------------------------- | -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `CHATFLOW`, or no type | Chatflow                                                      | `chatflows:view` on a GET, `chatflows:update` on a write       | Save a draft                                                                                                                    | Replay recent questions. There is no Start input. `datasetId` is accepted.                                                                                                                        |
| `AGENTFLOW`            | Agentflow                                                     | `agentflows:view` or `agentflows:update`                       | Save a draft                                                                                                                    | Replay by Start input. See the next table.                                                                                                                                                        |
| `HARNESS`              | Harness                                                       | `chatflows:view` or `chatflows:update`                         | Save a draft                                                                                                                    | Replay recent questions: the full prompts saved for the harness. A canvas whose harness file belongs to another team gets no questions. Another team's harness is a 404. `datasetId` is accepted. |
| `ETL`                  | Pipeline                                                      | `chatflows:view` or `chatflows:update`                         | Save a draft                                                                                                                    | No replay. The Publish dialog is a change list only. `GET .../check` returns `unavailable.code` `type`. `POST .../check` is 409 `The check works on chatflows and agentflows.`                    |
| `MULTIAGENT`           | Legacy multi-agent canvas, including a sequential-agent graph | `agentflows:view` or `agentflows:update`                       | Save a draft                                                                                                                    | The same refusal as a pipeline. The dialog still shows the box, with that message.                                                                                                                |
| `ASSISTANT`            | Assistant                                                     | `assistants:view` or `assistants:update`, after the route gate | No drafts. `PUT` save is 409 `This kind of flow saves straight to Live.` `GET` returns `"mode": "live"` and `"reason": "type"`. | The same refusal as a pipeline.                                                                                                                                                                   |

Draft routes are status, save, discard, settings, publish, and rollback. Check routes are `GET` and `POST` `/:chatflowId/check`, and `GET` and `DELETE` `/:chatflowId/check/:checkId`.

An agentflow check looks at the Start input on Live and on the draft. Both canvases that have a Start node must use the same input. A canvas with no Start node does not block the other side, so a flow that was never published can still be checked.

| Input Type          | Stored value     | What the check routes replay                                                                                        |
| ------------------- | ---------------- | ------------------------------------------------------------------------------------------------------------------- |
| **Chat Input**      | `chatInput`      | Recent questions. `datasetId` is accepted.                                                                          |
| **Form Input**      | `formInput`      | Recorded form submissions, newest distinct first. `datasetId` is 400.                                               |
| **Webhook Trigger** | `webhookTrigger` | Recorded webhook calls, newest distinct first. `datasetId` is 400.                                                  |
| **Schedule Input**  | `scheduleInput`  | Recorded schedule inputs, newest distinct first. A schedule that sent a form is read as a form. `datasetId` is 400. |

Two different starts, a Start node whose input type is blank, or no Start node on either canvas are not replayed. `POST .../check` is 409 `The check asks questions, so it works on agentflows that start with a chat message.` Chatflows and harnesses are not in this table: they have no Start input, and they replay questions.

Which flows have drafts: chatflows, agentflows, harnesses, ETL pipelines, and legacy multi-agent canvases. Assistant flows save straight to Live. A harness draft does not change `POST /api/v1/harnesses/:name/runs`. The canvas chat and Try it use `POST /api/v1/internal-prediction/:id`, which runs the draft when one exists and Live otherwise. Publish, Roll back, and `PUT /api/v1/chatflows/:id` write Live and update the roster the runs route serves. A pipeline draft does not change `POST /api/v1/etl/pipelines/:id/runs` or a schedule. Those read the published pipeline. `POST /api/v1/etl/pipelines/:id/preview` runs the canvas you send, which is the draft on the canvas, and does not write the store. When that preview omits the canvas, it runs the saved draft, or Live when there is no draft. The publish check runs on chatflows, agentflows, and harnesses. A harness accepts `datasetId`. A pipeline Publish lists the change list and does not run that check.

A draft holds the canvas only: nodes, connections, prompts and node settings. The flow's name, chatbot and API settings, and starter prompts still save straight to Live through the chatflow routes. `PUT /api/v1/chatflows/:id` also keeps writing Live, so scripts that update flows keep working. One exception: while a flow has unpublished changes, changing its type (through the chatflow API, Restore, or Roll back Live) returns 409 `This flow has unpublished changes. Publish or discard them before changing the flow's type.`, because the draft is a canvas of the current type. That check is the type write itself, so a draft saved after the read and before the write still blocks it. Publish also checks the type the draft was started on, and refuses a draft of another kind of flow with 409, even with `overwriteLiveChanges`; discard it to continue. A draft saved before Cuttlely recorded that type (a draft left from an earlier preview release) is refused the same way.

## Save the draft

`PUT /api/v1/flow-drafts/:chatflowId` with `{ "flowData": "<canvas JSON string>" }`. Live is not touched. Uploaded files in the draft are stored under their own name (`draft-<random>-<name>`), so a draft never replaces a file Live uses. A canvas identical to Live clears the draft instead.

400 when `flowData` is missing, not JSON, or has no `nodes` and `edges` lists. 409 when drafts are off, the flow's type has no drafts, or Publish instantly is on. 409 when the flow's type changed after this canvas was loaded (`This flow changed to another kind of flow after these edits started, so they can't be saved. Discard them to continue.`): the draft is not stored.

## Discard the draft

`DELETE /api/v1/flow-drafts/:chatflowId`. Throws the draft away. Live is not touched.

## Publish instantly

`PUT /api/v1/flow-drafts/:chatflowId/settings` with `{ "publishInstantly": true }`. With it on, canvas edits go straight to Live, as before drafts. Turning it on while the flow has unpublished changes returns 409; publish or discard them first. 400 when the value is not `true` or `false`. Turning it on while the passing test set is on returns 400 `Turn off the passing test set before turning on Publish instantly.`

The same route accepts `publishGate`:

```json
{ "publishGate": { "enabled": true, "datasetId": "<dataset id>", "evaluatorIds": ["<evaluator id>"], "threshold": 100 } }
```

`enabled: false` turns it off and leaves Publish as it is today. `threshold` is a whole number from 0 to 100; omit it and the server uses 100. Turning it on needs `datasets:view` and `evaluators:view` as well as permission to update the flow. The dataset and every evaluator are loaded in the flow's own workspace before anything is stored, the same way a dataset check loads them. 400 when drafts are off (`Drafts are off on this server.`), when **Publish instantly** is on (`Turn off Publish instantly before requiring a passing test set.`), when the flow is not a chatflow or an agentflow, when the agentflow starts with a form, a webhook, or a schedule (`A dataset check asks each row as a chat message. This flow starts with a form, so it cannot use a dataset.`, and the same sentence for a webhook or a schedule), when `datasetId` or `evaluatorIds` is missing from the body, or when `threshold` is not a whole number from 0 to 100. 403 when the caller can update the flow but cannot view datasets or evaluators. 404 `Dataset <id> not found` or `Evaluator <id> not found` when that id does not exist or belongs to another workspace. A dataset with no question the check can ask is 400 `This dataset has no questions the check can ask.` Nothing is stored in either case, and settings already saved stay as they were. Sending only `publishInstantly` does not change the gate.

## Publish

`POST /api/v1/flow-drafts/:chatflowId/publish`, optional body `{ "overwriteLiveChanges": true }`.

Saves the draft as Live through the normal chatflow update, so validation and file handling run as for any save. History gains a version of kind `publish`, titled `Published: <what changed>`, with the caller as its author. The draft is then cleared. If someone saved a newer draft while the publish ran, that draft is kept.

When the draft is `stale` (Live changed after it started), publishing would replace those Live changes, so it is refused with 409 unless the body has `"overwriteLiveChanges": true`. The save itself only goes through while Live is still the canvas and flow type that check was made against; if either changes during the publish, it returns 409 `Live changed while publishing, so nothing was published. Try again.`

```json
{
    "chatflow": {
        "id": "<flow id>",
        "name": "Bakery helper",
        "type": "CHATFLOW",
        "updatedDate": "2026-10-08T17:05:40.000Z",
        "flowData": "<Live canvas JSON>"
    },
    "version": {
        "sha": "afc07f3…",
        "kind": "publish",
        "published": true,
        "title": "Published: Changed System Message on Conversation Chain",
        "…": "…"
    },
    "unchanged": false,
    "recorded": true,
    "historyError": null,
    "status": { "mode": "draft", "draft": null, "…": "…" }
}
```

| Field          | Meaning                                                                                                                                               |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `version`      | The new history entry, in the [History API](./versioning-api.md#list-versions) list format, or `null`.                                                |
| `unchanged`    | `true` when Live already matched the draft. The draft is cleared once the same conditional save confirms Live still matches; history records nothing. |
| `recorded`     | `true` when the publish was added to history. `false` when history is off or the history write failed.                                                |
| `historyError` | Why the history write failed, when known. Otherwise `null`. Live is updated either way.                                                               |
| `status`       | The draft status after publishing.                                                                                                                    |

| Status | When                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 403    | No update permission for this type of flow.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| 409    | `Drafts are off on this server.`, `There are no unpublished changes to publish.`, a stale draft without `overwriteLiveChanges`, or the passing test set is on and the latest result is missing, failing, or out of date. That message names the threshold and the last result, for example `Publish needs a passing test set at 100%. The last result was 75% and failed.` A changed row, an added row, a changed evaluator, or a missing dataset or evaluator uses `The test set has changed since that check.` A flow with the setting off is unchanged. If an agentflow starts with a form, a webhook, or a schedule after the setting was turned on, the message says the dataset check cannot run and to turn the passing test set off. Publish stays blocked. |

## Roll back Live

`POST /api/v1/flow-drafts/:chatflowId/rollback` with `{ "sha": "<version id>" }`.

Sets Live to that version at once, with its name, type and category, the same way [Restore](./versioning-api.md#restore) does. History gains a version of kind `rollback`, titled `Rolled back Live to: <title> (<short sha>)`. An open draft is kept and is not marked stale, because this Live was chosen. While the flow has unpublished changes, a version of another kind of flow is refused with 409; see below.

The response is the [Restore](./versioning-api.md#restore) response plus `status`, the draft status afterwards. `chatflow.flowData` is the canvas that is Live after the roll back. The write lands only while Live is still the canvas that was read; a Live update in between returns 409 `Live changed while this was being saved, so nothing was changed. Try again.` 400 when `sha` is not 7 to 40 lowercase hex characters, 404 when the version is not in this flow's history, 409 when drafts or history are off, 403 without the update permission for the flow's type and the version's type.

## Publish check

Before Publish, the check asks a few recent real questions again, once to Live and once to the draft, and returns both answers side by side with the tokens and time each took. It is optional. Publish looks at a result only when the flow requires a passing test set, and then it reads the stored verdict, not these in-memory answers. How it looks in the Publish dialog: [Check recent questions before you publish](../how-to/versioning.md#check-recent-questions-before-you-publish). The gate: [Require a passing test set before you publish](../how-to/versioning.md#require-a-passing-test-set-before-you-publish).

Each question runs the model twice, so a check costs tokens on the flow's model account. The server caps each check:

| Limit          | Value                                                                                                                               |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| Questions      | `count` from 1 to 100, 4 in the dialog. A list sent without `count` is still at most 10. Each question is at most 2,000 characters. |
| Tokens         | `CUTTLELY_CHECK_MAX_TOKENS`, 100,000 by default. See [History settings](./versioning-settings.md#publish-check-limits).             |
| Time           | `CUTTLELY_CHECK_MAX_SECONDS`, 180 by default, and at most 60 seconds for any one run.                                               |
| At a time      | `CUTTLELY_CHECK_CONCURRENCY`, 2 by default, from 1 to 8. Live and the draft for one question still run one after the other.         |
| Checks at once | One per flow, three on the server.                                                                                                  |

When a token or time limit is reached, the check stops starting new questions. Questions already started finish, so the token total can go a little past the cap. A question counts only when both Live and the draft answered it. One question failing does not stop the others: that row has an error, and the rest continue. **Stop** keeps the questions that already finished.

Which questions run when you send `count`: the most recent ones people asked this flow, newest first. Message time decides the order, and the message id breaks a tie, newest id first. The same wording counts once. Capitals and extra spaces are ignored, and the newest copy is kept. The same count on the same history returns the same questions. It is not a random sample. Questions sent with files are left out. The server reads the newest messages, 200 at a time, until it has 100 different questions or it has read 2,000 messages or the history ends. If it stops at 2,000 messages before it has 100 different questions, `pastTruncated` is true: there may be older questions it did not reach. If fewer different questions exist than `count`, it compares every one it found.

What a check never does:

-   It never saves Live or the draft. The canvases run in memory.
-   It writes no chat messages, so replays do not show up in chat history, the flow's usage counts or its memory. Each run starts with empty memory.
-   It calls none of the flow's tracing or analytics providers, and adds no follow-up prompts or speech.
-   On an agentflow it writes no execution record. The replay does not resume a previous run and does not load one for state. It ignores any human input sent with the question, and stores no image or file that a model step generates. Choosing the inputs to replay does read execution records (up to 2,000), newest update first with the id breaking a tie.
-   It writes the questions, answers and canvases to no log. Results stay in the server's memory for 30 minutes and are lost on restart.

The check works on chatflows, agentflows and harnesses with unpublished changes. A chat-started agentflow must start with a chat message (Start input type **Chat Input**) in Live and in the draft, and the check replays questions. An agentflow whose start is a form, a webhook or a schedule is checked too, when Live and the draft use that same start: the check replays recorded inputs from recent executions instead of questions. A canvas with no Start node does not block the other side, so a flow that was never published can still be checked. Mixed starts, or a Start node with no input type, are refused. Legacy multi-agent and sequential-agent flows are not checked; that refusal stays `The check works on chatflows and agentflows.` On an agentflow, the tokens counted are the ones each model step reports (LLM and Agent steps); a Condition Agent step reports none. A model evaluator's tokens count toward the same cap. The grader reads `tokenUsage`, then `estimatedTokenUsage`, then usage metadata on the generation. A provider that reports usage in none of those places does not move the token total, so that check is bounded only by the time limit. If a model grade is aborted before every evaluator finishes, tokens already reported still count toward the cap, and the grader does not start another model evaluator. If the grading model cannot be started, text, JSON and numeric scores stay, and each model score is Error with the message `The grading model could not be started.`

A harness check reads the full user turns saved for that harness, newest first, and applies the same newest-distinct rule and the same caps. A canvas whose harness file belongs to another team gets no questions, and those prompts are not opened. Another team's harness is a 404, the same response as a missing name. The short preview on a run row is not the question. Secrets are redacted the same way as that preview (`sk-` and `xai-` tokens, `Bearer` values, and Postgres URLs), and the text is then cut at 2,000 characters with no ellipsis added. Distinctness uses that redacted text, so two prompts that share only the first 240 characters stay two questions. The server reads the newest 2,000 user turns. `pastTruncated` is true when that scan stops before it has 100 different questions. Starter questions are offered the same way as on a chatflow. Each question is run on the Live canvas roster and on the draft canvas roster. Both go through the canvas try: its own profile directory and a directory for each specialist, and its own gateway token, removed when the run finishes, when it throws, and when the check is stopped. A directory the runtime still has open is removed on the next start. A saved harness is left in place. The replay writes no chat message, no run-history row, no session turns and no analyst capture for that chat. A published run of the same harness, and a second check, use other chat ids and other profile directories. The tokens for a side are the route, specialist and handoff tokens the run already added together. Cached tokens are part of the prompt count and are not added again. The estimated cost uses those same lines, grouped by model, which is the usage write stored under the harness name. Daily token usage for that replay is the same single write as a canvas try. A specialist with Shell, Browser, Code execution or Files is a risky step and is skipped unless `includeRiskySteps` is true. SQL tools keep the try profile's refusal. A saved dataset's rows are the questions, in the saved order, and they replay on both rosters. Empty rows and rows longer than 2,000 characters are skipped. `questions` or `count` sent with `datasetId` is 400 `Send a datasetId on its own. Do not send questions or count with it.`

For a form, webhook or schedule start, `count` selects the newest distinct recorded inputs, up to 100, from this flow's execution records (newest update first). A form input is the submitted form. A real run stores it as lines of `name: value` on the Start step (for example `loaf: rye` then `count: 2`). Each line is split on the first `: `, so a value may contain a colon, and the value comes back as a string. A row from this version starts with a marker line, and a backslash in a value is an escape. That marker stays on the stored Start output. The replay, like the original run, sends each node the readable lines, in the stored field order, with a real line break and a single backslash. Two orders of the same fields still count as one input. An older row whose line break leaves a line with no field name is not replayed. An older row has no marker, and a backslash in it stays as typed. A schedule that sends a form is stored and read the same way. A form already stored as an object is used as stored. A webhook input is the body, the query and the headers that change what the flow does. A schedule input is the form that was sent, read the same way as a form start, or the trigger text when the schedule did not send a form, including the single-space text used when the schedule sends no input. Webhook headers that change on every delivery do not count as a different input and are left out of the stored payload: `date`, `user-agent`, `content-length`, `forwarded`, `x-forwarded-*`, and any header whose name contains `request-id`, `requestid`, `trace`, `signature` or `timestamp`. Key order is ignored. The server reads executions 50 at a time, newest `updatedDate` first and `id` descending when the time ties, until it has 100 different inputs or it has read 2,000 executions or the history ends. `pastTruncated` is true when it stops at 2,000 before it has 100. There are no starter questions on this path, and extra `questions` sent with `count` are not added. When `count` is sent and there are no executions to replay, the response is 400 and names how to record one: a form says `No past runs exist yet. Submit the form once, then check again.`, a webhook says `No past runs exist yet. Call the webhook once, then check again.`, and a schedule says `No past runs exist yet. Wait for the schedule, or trigger it once, then check again.` That is not a refusal of the flow: the setup still returns `unavailable: null`, `replayInputs: true` and `replaySource` set to `form`, `webhook` or `schedule`. Each recorded input includes `source` (that same word) and `date` (when the run was stored). The dialog shows both above `preview`. A check case for that input carries the same `source` and `date`. Each stored question is canonical JSON (`{"form":...}`, `{"webhook":...}` or `{"question":...}`). Header and query names that are `authorization` or `cookie`, or that contain `token`, `secret`, `key`, `password` or `signature`, have the value `[REDACTED]` in that JSON, in `preview`, and in the check cases, including when the name is nested (`user[password]` stored as `{ "user": { "password" } }`, or the same shape inside a header). Arrays are walked the same way. The raw value is not returned. `preview` is the short line the dialog shows. For a webhook it is the body. When another kept row has the same body, `preview` also includes the query or the differing header names (sensitive values still `[REDACTED]`). The webhook stores Authorization as `[REDACTED]` before the execution is saved, so two calls that differ only by that header are one recorded input and the preview is the body alone. The replay sends the masked input with the same no-persistence behavior as a chat question: a form without a question, a webhook as a webhook call, a schedule as a scheduled call. It writes no chat message and no execution record. A risky step is not run unless `includeRiskySteps` is true, so the replay makes no outbound call from that step.

### Steps that act for real

Some steps do more than answer: they send a request, write to a database or vector store, run custom code or call an assistant that keeps its own threads. Replaying them could repeat that action, so the check refuses to run a flow that has one, in Live or in the draft, unless the request says to run it anyway. Steps counted as risky:

-   Any node outside these groups: Chat Models, LLMs, Embeddings, Prompts, Output Parsers, Text Splitters, Retrievers, Moderation, Document Loaders, Record Manager, Vector Stores, Chains, Agents, Memory, Tools and Utilities. A node the check does not know counts as risky.
-   In those groups: Vectara upsert, POST API chain, OpenAPI chain, SQL database chain, Cypher QA chain, OpenAI Assistant, Custom JS Function and If Else Function.
-   Memory other than Buffer Memory, Buffer Window Memory, Conversation Summary Memory and Conversation Summary Buffer Memory. Those four read Cuttlely's own chat history, which a replay starts empty and never writes; other memory keeps turns in its own store.
-   Tools other than read-only ones such as Calculator, the web search tools, Requests Get, Web Scraper and retriever or chain tools.
-   Utilities other than Set Variable, Get Variable and Sticky Note.
-   The flow's **Post-processing** code.

On an agentflow, the steps counted as risky:

-   Custom Function, HTTP, Execute Flow and Human Input steps, and any agentflow step the check does not know.
-   A Tool step, unless its tool is one of the read-only tools above.
-   An Agent step with a tool that is not read-only, or with a tool that asks a person to approve it. An Agent with no tools, or only read-only ones, is safe. Its built-in provider tools (web search, code run by the model provider) count as read-only.
-   Start, LLM, Agent, Condition, Condition Agent, Retriever, Direct Reply, Loop, Iteration and Sticky Note steps are safe.

### Check setup

`GET /api/v1/flow-drafts/:chatflowId/check`

```json
{
    "unavailable": null,
    "questions": [{ "text": "Do you have gluten-free bread today?", "date": "2026-10-08T16:12:03.000Z" }],
    "pastCount": 1,
    "pastTruncated": false,
    "riskySteps": [],
    "limits": {
        "maxQuestions": 100,
        "defaultQuestions": 4,
        "maxQuestionChars": 2000,
        "maxTokens": 100000,
        "maxSeconds": 180,
        "concurrency": 2
    },
    "liveEmpty": false,
    "replayInputs": false,
    "replaySource": null,
    "check": null
}
```

| Field           | Meaning                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `unavailable`   | Why a check can't run now, or `null`. `code` is `off` (drafts are off), `type` (not a chatflow, an agentflow or a harness; legacy multi-agent flows stay here, with `The check works on chatflows and agentflows.`), `no-draft` (nothing to check) or `start` (the two versions do not start the same way, or there is no Start input to replay), with a `message` to show. A form, webhook or schedule start with no past runs is not `unavailable`.                                                                                                                         |
| `questions`     | Up to 100 recent questions people asked this flow, through the API, embeds and shared links or the canvas test chat, newest first and without repeats. Questions sent with files are left out. Then up to 10 of the flow's starter questions that nobody asked yet, marked `"starter": true` with an empty `date`, so a new flow has questions to check. When `replayInputs` is true, these are recorded inputs instead: canonical JSON, newest first, with no starter rows. Each one has `source` (`form`, `webhook` or `schedule`) and `date` (when that run was recorded). |
| `replayInputs`  | `true` when the check replays recorded form, webhook or schedule inputs. `false` for chatflows and chat-started agentflows.                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `replaySource`  | `form`, `webhook` or `schedule` when `replayInputs` is true. `null` for a chatflow, a chat-started agentflow, or a harness. The dialog uses it for the empty state.                                                                                                                                                                                                                                                                                                                                                                                                           |
| `pastCount`     | How many of `questions` are past questions, not starter questions. At most 100. When `replayInputs` is true, how many distinct recorded inputs were found.                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `pastTruncated` | `true` when the scan stopped at 2,000 messages (or 2,000 executions, for a form, webhook or schedule start) before it found 100 different past questions or inputs.                                                                                                                                                                                                                                                                                                                                                                                                           |
| `riskySteps`    | The steps that act for real, as `{ "id", "label" }`. Empty when there are none.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `limits`        | The limits above, as this server has them. `maxQuestions` is 100. `defaultQuestions` is 4, which the dialog selects first. `concurrency` is how many questions run at once.                                                                                                                                                                                                                                                                                                                                                                                                   |
| `liveEmpty`     | `true` when Live has no cards yet, as with a flow saved only as a draft so far. Its check asks only the draft.                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `check`         | The flow's latest check, in the shape below, or `null`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |

### Start a check

`POST /api/v1/flow-drafts/:chatflowId/check` with `{ "count": 4, "questions": ["…"], "includeRiskySteps": false }`.

A pipeline runs the same call with [`cuttlely check`](../how-to/ci-gate.md). The command sends `count` 4, polls [Read a check](#read-a-check) until the check finishes, and exits 1 when `--fail-on-changed` sees a Changed answer. The key needs both permissions for the flow type, because this route needs update and the poll needs view: `chatflows:view` and `chatflows:update`, or `agentflows:view` and `agentflows:update`. [Scored mode](../how-to/ci-gate.md#scored-mode) sends `datasetId`, `evaluatorIds`, and `threshold` instead of `count`, and exits on `verdict.result`. It does not compute that verdict. That key also needs `datasets:view` and `evaluators:view`.

`count` is optional. When it is sent, it must be a whole number. A number below 1 counts as 1, and above 100 as 100. The server then chooses that many past questions by the rule above. For a chatflow or a chat-started agentflow, `questions`, if also sent, are extra questions added after those, still within 100 altogether, with repeats dropped. For a form, webhook or schedule start, send `count` on its own. Sending `questions` as well is refused: the server does not add them and does not return 202. When `count` is omitted, the request is the older one: `questions` is required, at most 10, and the server runs that list. That default is unchanged. `{ "count": 4 }` on its own is still that request. Answers 202 with the check, `status` `running`. The runs happen in the background, a few questions at a time; read progress with the next route. `completed` is how many questions both sides have answered, out of `total`. If the client goes away while the questions, a dataset, or recorded inputs are loading, nothing is started. A close after the check has been stored stops that check.

Two more fields are optional:

| Field          | Meaning                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `datasetId`    | A dataset in this workspace. Its rows, in sequence order, are the questions: row input is the question, row output is the expected answer. At most 100 rows. A row with an empty question, or a question longer than 2,000 characters, is skipped. Do not send `questions` or `count` with it. The caller also needs `datasets:view`. A chatflow, a chat-started agentflow, and a harness accept it. A flow that starts with a form, a webhook or a schedule is refused.                                                                                        |
| `evaluatorIds` | Evaluator ids in this workspace, scored on each answer for Live and for the draft. Repeats are dropped. The caller also needs `evaluators:view`. Omit it, or send `[]`, for the comparison with no score.                                                                                                                                                                                                                                                                                                                                                       |
| `threshold`    | Only with `datasetId`. A whole number from 0 to 100. Omit it and the server uses 100. The finished check reports `verdict` for the draft: `passed` when the draft pass rate is at least this number, otherwise `failed`. Errored scores count as not passed. A check with no scores is `failed`. Sending `threshold` without `datasetId` is refused. A check without a dataset has `verdict` `null`. A harness check can report that verdict. It does not store a pass, and it does not satisfy Publish, because a harness cannot turn the passing test set on. |

| Status | When                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 400    | `count` is not a whole number, `questions` is not a list of text, a question is empty or longer than 2,000 characters, the list is empty when `count` is omitted, the list has more than 10 questions when `count` is omitted (or more than 100 when `count` is sent for a chatflow, a chat-started agentflow, or a harness), there are no past questions for `count` and no extra questions, there are no past runs to replay for a form, webhook or schedule start (`No past runs exist yet. Submit the form once, then check again.`, `No past runs exist yet. Call the webhook once, then check again.`, or `No past runs exist yet. Wait for the schedule, or trigger it once, then check again.`), a form, webhook or schedule start sends `questions` together with `count` (`Questions are not used for a form, webhook or schedule start. Send count on its own.`), `includeRiskySteps` is not `true` or `false`, `datasetId` is sent with `questions` or `count`, `datasetId` is empty, `evaluatorIds` is not a list of ids, the dataset has no question the check can ask, the flow starts with a form, a webhook or a schedule and the request sent `datasetId`, `threshold` is sent without `datasetId`, or `threshold` is not a whole number from 0 to 100. |
| 403    | The caller can update the flow but does not have `datasets:view` (when `datasetId` is sent) or `evaluators:view` (when `evaluatorIds` lists any id).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| 404    | `datasetId` or an id in `evaluatorIds` is missing, or it belongs to another workspace. Nothing is started.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| 409    | Drafts are off, the flow is not a chatflow, an agentflow, or a harness (a pipeline, a legacy multi-agent flow, and an assistant are refused with `The check works on chatflows and agentflows.`), the two versions do not start the same way, there are no unpublished changes, a check is already running for this flow, or the flow has risky steps and `includeRiskySteps` is not `true`. The message names the steps. The risky-step rule is the same for a chat start and for a form, webhook or schedule start. A dataset check on a form, webhook or schedule start is 400, not this 409.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| 429    | `Too many checks are running on this server. Try again in a minute.`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |

### Read a check

`GET /api/v1/flow-drafts/:chatflowId/check/:checkId`. 404 `That check was not found. Run it again.` when the id is not this flow's latest check, or it has expired.

```json
{
    "id": "<check id>",
    "status": "done",
    "stopReason": null,
    "error": null,
    "startedDate": "2026-10-08T17:10:00.000Z",
    "finishedDate": "2026-10-08T17:10:05.000Z",
    "total": 1,
    "completed": 1,
    "draftChanged": false,
    "includeRiskySteps": false,
    "limits": {
        "maxQuestions": 100,
        "defaultQuestions": 4,
        "maxQuestionChars": 2000,
        "maxTokens": 100000,
        "maxSeconds": 180,
        "concurrency": 2
    },
    "liveEmpty": false,
    "selection": { "requested": 4, "available": 1, "used": 1, "truncated": false },
    "cases": [
        {
            "question": "Do you have gluten-free bread today?",
            "expected": null,
            "live": {
                "text": "Yes, we bake it on Tuesdays.",
                "error": null,
                "tokens": 44,
                "ms": 657,
                "estimatedCostUsd": 0.000018,
                "price": "known",
                "unpricedModels": []
            },
            "draft": {
                "text": "Yes, every day.",
                "error": null,
                "tokens": 45,
                "ms": 525,
                "estimatedCostUsd": null,
                "price": "no price",
                "unpricedModels": ["custom-bakery"]
            },
            "same": false
        }
    ],
    "summary": {
        "ran": 1,
        "same": 0,
        "changed": 1,
        "errors": 0,
        "liveTokens": 44,
        "draftTokens": 45,
        "liveMedianMs": 657,
        "draftMedianMs": 525,
        "liveEstimatedCostUsd": 0.000018,
        "draftEstimatedCostUsd": null,
        "livePrice": "known",
        "draftPrice": "no price"
    }
}
```

| Field          | Meaning                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `status`       | `running`, `done`, `stopped` (a limit or Stop ended it early) or `failed` (it could not run; `error` says so).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `stopReason`   | `tokens`, `time` or `stopped`, when `status` is `stopped`. Otherwise `null`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `completed`    | Questions both sides have answered, out of `total`. With `liveEmpty`, questions the draft has answered.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `liveEmpty`    | `true` when Live had no cards when the check started. Then only the draft runs: `live` stays `null`, `same` stays `null`, and `summary` counts the draft's answers, with Live tokens 0 and no Live time.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `draftChanged` | `true` when the draft was saved, published or discarded after the check started, so its answers may be out of date.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `cases`        | One per question. `expected` is the dataset row's output, or `null` when the question did not come from a dataset. `live` and `draft` are `null` until that side has run. `text` is the answer, cut at 4,000 characters, or `null` with an `error` when the run failed. `tokens` is `null` when the model reported none. `estimatedCostUsd` is an estimate in US dollars, or `null` when `price` is `no price` or that side did not run. `price` is `known`, `partial`, or `no price`. A missing price is not zero. When `evaluatorIds` was sent, each side has `scores`: `{ "id", "name", "result" }` with `result` `Pass`, `Fail` or `Error`, in the order of `evaluatorIds`. An answer that failed to run scores `Error`, not `Fail`. A model grade that is only a number is `Error`. A yes or no in that grade, or a `result` of `Pass` or `Fail`, is used as the score. Numeric evaluators read `totalTokens` when the check recorded a token total, and `apiLatency`, `llm` and `chain` from the run's wall-clock time. A prompt-token measure, a completion-token measure, or a total-token measure with no number scores `Error`, not `Fail`. That Error counts in the pass rate. A check with no evaluators leaves `scores` off. A recorded input also has `preview`, `source` and `date`. |
| `same`         | `true` when both answers match, ignoring case and spacing. `false` when they differ or either side failed. `null` until both have run. Answers from a model can vary between runs even with no change.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `selection`    | Set when the request sent `count`. `requested` is the count after clamping, `available` is how many distinct past questions were found (at most 100), `used` is how many of those were included, and `truncated` means the scan stopped early. `null` when the request sent a question list and no count, and when it sent `datasetId`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `summary`      | Counts over the questions both sides answered: how many `same`, `changed` and with `errors`, total tokens per side, the middle (median) time per side in milliseconds, and an estimated cost per side. That total groups the answers' token lines by model and prices each model once. The figure on one answer is priced on its own and can differ from the total by one hundred-millionth of a dollar. `livePrice` and `draftPrice` are `known`, `partial`, `no price`, or `null` when that side did not run. `liveEstimatedCostUsd` and `draftEstimatedCostUsd` are estimates in US dollars, or `null` when that side has no price. When evaluators ran, `summary.scores.live` and `summary.scores.draft` add `passed`, `failed`, `errored` and `passRate` (passed divided by passed + failed + errored, as a percentage from 0 to 100 with one decimal). With an empty Live, only `draft` is set. Without evaluators, `scores` is left off.                                                                                                                                                                                                                                                                                                                                                     |
| `verdict`      | `null` unless this was a dataset check and it has finished (`status` `done`). Then `{ "result": "passed" or "failed", "threshold", "passed", "failed", "errored", "passRate" }` for the draft. `result` is `passed` when `passRate` is at least `threshold`. Errored scores are in that rate's denominator, so they are not passed. `passRate` `null` (no scores) is `failed`. A running, stopped, or failed check, and any check without a dataset, has `verdict` `null`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |

Reading a check does not return 403 when the caller can view the flow but not datasets or evaluators. On a dataset check, that caller gets an empty `question` and `expected` `null`: the row input and the expected output are not in the response. Each score is `{ "result" }` only, with no evaluator id and no name. Pass, Fail, Error and the pass rate stay. A caller with `datasets:view` and `evaluators:view` receives the question, the expected answer, and the evaluator id and name. Recent questions and recorded form, webhook and schedule inputs are not dataset rows, so they stay. The same rules apply to the check included in [Check setup](#check-setup).

### Stop a check

`DELETE /api/v1/flow-drafts/:chatflowId/check/:checkId`. Stops the run in progress and keeps the questions already answered. Returns the check, which reads `stopped` once the run has ended. Stopping a finished check changes nothing.
