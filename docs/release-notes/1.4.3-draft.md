# Cuttlely 1.4.3

Draft release notes, 2026-10-24. This file is not a release. Versions are unchanged, and nothing here is tagged.

## Summary

1.4.3 is the fix release after 1.4.2. It covers harness startup and delete, asset downloads, safer LangSmith and credential handling, and analyst queries. Analyst queries on the current line match 1.4.2: [#294](https://github.com/cuttlely/cuttlely/pull/294) reverted the checks from [#292](https://github.com/cuttlely/cuttlely/pull/292). Three pull requests are still open and are marked pending merge: [#293](https://github.com/cuttlely/cuttlely/pull/293), [#291](https://github.com/cuttlely/cuttlely/pull/291) and [#289](https://github.com/cuttlely/cuttlely/pull/289).

## Fixes

-   Harness Prime's profile starts its own servers. Each specialist starts its own bridge, with its own gateway token. A raw MCP server on a specialist stays on that specialist. ([#283](https://github.com/cuttlely/cuttlely/pull/283))
-   The assets preset downloads a logo, image, PDF or font with `fetch` and `fetch_asset`. Every hop, redirects included, must resolve to a public address, and the helper connects to the address it checked. The body cap is 10 MB by default and 50 MB at most. The whole fetch, redirects included, is 20 seconds by default and 60 seconds at most. This path sends a browser-like user agent. `fetch_asset` requires a successful image, PDF or font response, writes the file and prints the byte count. `use_dir` is part of the kit, and the older name `asset_kit` imports the same kit. A tool result that reports an error, a timeout, an interrupt or a non-zero exit code is a failed step. A failed tool preview keeps its beginning and its end, up to 1,200 characters, so the address and the status stay in view. A successful preview is cut at 500 characters. ([#281](https://github.com/cuttlely/cuttlely/pull/281))
-   Deleting a harness, from its card or by deleting its canvas, removes that harness's agent runtime profile, the profiles of its specialists and their workspaces. Gateway tokens are revoked first. When revocation fails, nothing is removed and the harness stays. Removal matches the exact harness name, so a different name stays, including a name that differs only by letter case. ([#285](https://github.com/cuttlely/cuttlely/pull/285))
-   LangSmith tracing and credential saves use safer defaults. An upload-failure log records the credential id, the field names, the length of the credential value, the endpoint origin and the project. A failed response passed on to the tracing client keeps the status and the short body, and only the `retry-after` and `content-type` headers. A connection string counts as masked when it contains the mask as shown, a percent-encoded bullet in any letter case, or a password that does not percent-decode. A replica-set connection string that the URL parser refuses is read from its authority, and its password is masked the same way. A flow LangSmith credential with no value gets no tracing client, so tracing for that flow stays off and the server's LangSmith settings stay unused for that credential's endpoint. Credential fields have no reveal control. ([#284](https://github.com/cuttlely/cuttlely/pull/284))
-   Analyst query checks added in [#292](https://github.com/cuttlely/cuttlely/pull/292) are reverted. Those checks refused text-search configuration types (`regconfig` and `regdictionary`). Queries follow the 1.4.2 rules. ([#294](https://github.com/cuttlely/cuttlely/pull/294))
-   **Pending merge, [#289](https://github.com/cuttlely/cuttlely/pull/289).** Chat answers keep an ordinary slash. A token that is only `/`, `\` or `~` is shown as written, so a figure such as `2,499 consumed / 6,672 entitled` stays intact. Fractions, dates and `https` addresses stay as written. A real server path is still hidden, including a path that continues after a lone slash. On the same pull request, the assets fetch check judges an IPv4-mapped address by the IPv4 address it carries. A private mapped address is refused.

## Changes

-   At startup, Cuttlely logs profiles whose harness has no store file. It removes them only when `CUTTLELY_HARNESS_ORPHAN_SWEEP=delete`. The sweep leaves a saved harness (any letter case), a canvas try, anything changed in the last 10 minutes, and any profile it cannot confirm is inside the profiles directory. It does not follow a symbolic link. ([#285](https://github.com/cuttlely/cuttlely/pull/285))
-   **Pending merge, [#293](https://github.com/cuttlely/cuttlely/pull/293).** The PostgreSQL MCP node gains an analyst guard and an **Allowed functions** list, one entry per line, under the node's additional parameters. Only the person who builds the flow sets it. It is saved with the flow, and the model cannot add to it. Write `schema.fn(argtypes)` for one signature, with the argument types as the refusal prints them, or `schema.fn(*)` for every overload of that name. A bare name matches nothing. A line that starts with `#` is ignored. `regconfig` and `regdictionary` are allowed, so text search (`to_tsvector`, `plainto_tsquery`, `ts_headline`) and a materialized view that stores a text-search configuration run while a table selection is set. Object-identifier types (`regclass`, `regtype`, `regproc`, `regprocedure`, `regoper`, `regoperator`, `regnamespace`, `regrole`, `regcollation`), including a multirange over one of those types, are refused only while a table selection is set. `pg_tablespace_location` is on the refused built-in list. With a table selection, a user function outside `pg_catalog` runs on its own only when it is SQL with a `BEGIN ATOMIC` body, `STABLE` or `IMMUTABLE`, not `SECURITY DEFINER`, has no `proconfig`, is not owned by a superuser, has no `pg_class` relation among its `pg_depend` references, and every function it calls passes the same rule. The same rule applies to functions reached through views. With no table selection, a SQL or PL/pgSQL function outside `pg_catalog` runs when it is `STABLE` or `IMMUTABLE`, not `SECURITY DEFINER`, has no settings of its own and is not owned by a superuser. Any other user function needs an **Allowed functions** entry.
-   **Pending merge, [#291](https://github.com/cuttlely/cuttlely/pull/291).** Saved harness profiles written by an older compiler are compiled again when the server starts, before the agent runtime reads them. A harness that was never compiled is left as it is. A second start in a row finds nothing to compile. A compile that fails moves that harness's `config.yaml` files aside as `config.yaml.outdated`, parent and specialists included, so the runtime loads neither a stale file nor a half-written one. `GET /api/v1/ping` answers 503 with the body `profiles compiling` and `Retry-After: 30` while that pass is the startup gate. The harness gateway `/health` stays 503 until the pass finishes.

## Upgrade notes

-   Profiles left behind by a delete from before this cleanup are logged at startup and kept. To remove them, set `CUTTLELY_HARNESS_ORPHAN_SWEEP=delete` and start again. The log line is `orphan profile sweep (dry run): would remove profiles/<name> of harness "<id>"`. A saved harness, a canvas try and anything changed in the last 10 minutes stay. ([#285](https://github.com/cuttlely/cuttlely/pull/285))
-   **Pending merge, [#293](https://github.com/cuttlely/cuttlely/pull/293).** Scoped analyst nodes may need the new **Allowed functions** setting. A PostgreSQL MCP node with a table selection refuses PL/pgSQL helpers and string-body SQL helpers unless they are listed. A SQL helper with a `BEGIN ATOMIC` body that meets the rule above still runs on its own. Add one line per function, in either form:

    ```text
    schema.fn(argtypes)
    schema.fn(*)
    ```

    Use the argument types from the refusal. `schema.fn(*)` covers every overload. Publish the flow after you save the list. The node login needs `TEMP` (a hot standby cannot run these queries). Analyst statements run with `standard_conforming_strings` on, so a backslash inside `'...'` is a plain character; use `E'...'` when you want an escape. A database that has a type, operator class, or text-search parser or template whose functions are outside `pg_catalog` (such as `citext` or `unaccent`), a foreign-data wrapper, an enabled event trigger, or a json cast, index expression or constraint that calls a function outside `pg_catalog`, refuses every node query. Point the credential at another database, or remove those objects. Use a dedicated read-only login: `CONNECT`, schema `USAGE`, `SELECT` and `TEMP`, and no `CREATE` for untrusted roles on schemas in that login's search path.

-   **Pending merge, [#291](https://github.com/cuttlely/cuttlely/pull/291).** The first start after this change recompiles saved harness profiles before the agent runtime starts. While that pass is the startup gate, `GET /api/v1/ping` returns 503 (`profiles compiling`, `Retry-After: 30`). The start script treats a gateway 503, and a probe that connects and gets no answer within 400 ms, as still compiling. It waits up to `CUTTLELY_GATEWAY_STARTING_WAIT_SECONDS` (default 180 seconds, and never more than 300; a value that is not a whole number uses 180). A compile that is still running at that cap continues in the background. Ping can then return 200. Chat and prediction stay 503, with `Retry-After: 30` and the message `Cuttlely is compiling agent profiles. Try again in a minute.`, until the compile finishes. The agent runtime starts when the gateway health check answers. `CUTTLELY_GATEWAY_HOLD_UNTIL_BOOT` defaults to `1` in the start script, so gateway `/health` answers 503 from the first request until the boot pass finishes. One profile that cannot be read, or whose older `config.yaml` cannot be moved aside, is logged and skipped. The other profiles still start. If the profiles folder itself cannot be checked, ping stays 503 until the wait cap, and the runtime is then allowed to start.
-   [#289](https://github.com/cuttlely/cuttlely/pull/289) (pending merge) needs no setting change. After it merges, answers keep ordinary slashes, and real server paths stay hidden.
