Vendored from NousResearch/hermes-agent at the commit in UPSTREAM_COMMIT (v0.21.4+canary). CUTTLELY_VENDOR.lock records the upstream, the ref, the commit and a fingerprint of this folder.
Cuttlely uses the agent loop, delegation, memory, skills, MCP client, tool registry, profiles, and API server.
Chat UIs, the TUI, and messaging platforms are not started. Hermes binds 127.0.0.1. The desktop and mobile apps, optional skills, the terminal UI, the dashboard source, upstream scripts and the ACP adapter are left out (CUTTLELY_EXCLUDE.txt); pnpm verify imports the modules Cuttlely runs (scripts/hermes-import-smoke.mjs).
The Cuttlely harness client is the only execution seam and calls POST /v1/runs.
This folder is upstream minus the paths in CUTTLELY_EXCLUDE.txt (and upstream files that the .gitignore files match), plus the cuttlely patches in patches/. Each patch file opens with what it changes and why, and each Hermes file belongs to at most one patch.
Re-vendor with pnpm hermes:vendor <tag-or-commit>. It fetches upstream, drops the excluded paths, applies the patches three-way in a staging copy outside the repo, and only then replaces this folder. If a patch does not apply it stops and names it: fix the staging copy, then pnpm hermes:vendor --continue, or pnpm hermes:vendor --abort.
To change a Hermes file, edit it here, then run pnpm hermes:vendor --save-patches (add --new <name> --message "<what and why>" for a file no patch owns yet). pnpm verify runs pnpm hermes:vendor --check, which fails if an excluded path comes back, a patch no longer matches the files, or anything here changes outside the script (this notes file excepted).
Maintainer guide: docs/reference/hermes-upgrades.md (upgrade steps, patch conflicts, changing a Hermes file).
Patches:
0001 delegate roster: tools/delegate_tool_toolsets.py grants each specialist the allowlist stored in that profile's harness-roster.json, and the chief profile only enables delegation, memory, and session_search. run_agent.py and tools/delegate_tool.py keep a harness chief's delegation synchronous.
0002 MCP retry: tools/mcp_tool_cuttlely.py, with hooks in tools/mcp_tool.py, tools/mcp_tool_discovery.py and tools/mcp_tool_handlers.py, retries a startup tools/list that returns nothing or cannot connect, rediscovers tools when a call finds the server toolless, and keeps an MCP result with cuttlelyOutcome "expected" off the circuit breaker. Real transport failures still open it, per chat when the call has a session id. The analyst tool call also receives that session id as _cuttlelyScope so a page cursor cannot be reused from another chat. The bridge removes it before the tool schema. Test: tests/tools/test_cuttlely_mcp_retry.py.
0003 API server MCP wait: gateway/platforms/api_server.py waits for MCP discovery before it builds the agent for a run. The run usage also carries cache_read_tokens (cached prompt tokens) for Cuttlely's turn report.
0004 skills_read toolset: toolsets.py adds the read-only "skills_read" toolset (skills_list and skill_view, no skill_manage). A specialist with playbooks gets it; the playbooks are written as skills under that profile's skills/harness-playbooks folder.
0005 models.dev offline: agent/models_dev.py makes no models.dev request unless CUTTLELY_MODELS_DEV=1 (set it in Cuttlely's environment to opt in). Memory and disk caches still serve, and capability, context and pricing lookups without data fall through to the other sources, as when models.dev is unreachable.
