# Changelog

This file records every notable change to Cuttlely. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and Cuttlely uses [Semantic Versioning](https://semver.org/spec/v2.0.0.html). [Releases and support](./docs/releases.md) explains what counts as a breaking change and which versions get fixes.

## [Unreleased]

### Added

-   Trusted-output CSV reports have an opt-in `escapeFormulas` setting on the CSV contract, off by default. When it is on, a header or cell that starts with `=`, `+`, `-`, `@`, a tab or a carriage return gets a leading `'`, which keeps spreadsheet apps from treating the cell text as a formula. Plain signed numbers such as `-5`, `+5` or `-1e3` are left unchanged. With the setting off, files are exactly as before. See [Trusted outputs](./docs/reference/trusted-outputs.md).

### Fixed

-   Harness planning can ask a fixed question for essential missing scope before running a specialist. Protected interpretation recognizes equivalent source timestamp displays without accepting invented times or business quantities, and tool-free repair retains more evidence for a single captured report.

-   Agent-team follow-ups can retain the exact source-backed record selection and order across shortened history and specialist changes. The shared router distinguishes factual presentation from analysis and recognizes shared query scopes when choosing an owner for a complete deliverable. Protected analysis gets one tool-free, revalidated repair for unsupported claims, and an unmapped source fallback presents bounded business records instead of nested field paths. Equivalent duration abbreviations and written monetary scales retain unit and denomination checks. See [team tuning](./docs/how-to/tune-agent-team.md#carry-intent-and-record-scope-between-turns).

## [1.4.10] - 2026-11-01

### Added

-   Trusted-output CSV reports are delivered with their source tables: complete rows, up to the contract limit. The CSV contract may set `maxRows` from 1 through 10,000 (the default stays 100) to attach a complete table of up to that many rows, and `reportPath` to append a source-owned Markdown report after the attachment note. Delivery is refused when the table is incomplete, over the contract limit, or the report is missing; the model cannot supply a replacement. A specialist can have up to 32 trusted-output contracts, up from 16. See [Trusted outputs](./docs/reference/trusted-outputs.md). [#369](https://github.com/cuttlely/cuttlely/pull/369).

### Changed

-   The settings panel of the **Postgres (MCP)** node is redesigned. It is listed as **Postgres (MCP)** in a **Database** group, and searching `postgres` or `mcp` still finds it. Its fields sit in **Data source**, **What it can see**, **Model**, **Limits** and **Advanced**, with clearer labels. A badge says where queries go, and a list that cannot load shows a note with **Retry**. Wired cards show **Used by:** and **Data:** notes. Run trace chips read like **Query · 4 rows**, and a result table has **Show SQL**, **Copy** and **CSV** (**Copy preview** and **Preview CSV** when the run card kept only part of the result). The settings panel is wider, can be resized by dragging its edge (the width is remembered in the browser) and has an **Expand** button. The analyst extras show only when the server's analyst settings turn them on, and those settings are off by default: the searchable pinned query list, where a long list starts folded and a pin opens in a dialog, needs `CUTTLELY_PINNED_QUERIES`, and the **Sandbox** badge needs `CUTTLELY_ANALYST=auto`. Labels are display only: saved harnesses, node names, field names and runs are unchanged. A new Postgres (MCP) card starts with **Query** ticked; saved cards keep their tools. See [Analyst mode](./docs/how-to/analyst.md#the-postgres-mcp-card). [#370](https://github.com/cuttlely/cuttlely/pull/370).

### Fixed

-   A JSON setting on a node, credential or document store whose saved value is only whitespace or is not valid JSON, for example a value cut off partway, no longer crashes the page with "Unexpected end of JSON input". The JSON editor opens it as an empty object (`{}`) and writes nothing back until you edit it; valid values open as before. An agentflow node whose saved built-in tool list cannot be read shows no built-in tools, and a multi-select field whose saved value cannot be read shows nothing selected, instead of crashing the page. [#367](https://github.com/cuttlely/cuttlely/pull/367).

-   When a page throws while it loads or renders, Cuttlely shows a short error page with **Reload**, **Go home** and collapsible error details instead of the default router error screen. [#367](https://github.com/cuttlely/cuttlely/pull/367).

## [1.4.9] - 2026-10-31

### Added

-   **Auth / SSO** in **Admin** shows which method ordinary sign-in uses, **Local login**, **Generic OIDC** or **WorkOS**, to an owner or a role with **Authentication: Manage**. Changing the method needs a recent sign-in, a review step and typing `END SESSIONS`, and it ends every interactive session; API credentials stay enabled. Until an active owner has a usable local password, the page and an application banner say that owner recovery is not ready, and activating WorkOS or generic OIDC is refused. See [Choose the sign-in method](./docs/how-to/auth-sso.md). [#352](https://github.com/cuttlely/cuttlely/pull/352), [#360](https://github.com/cuttlely/cuttlely/pull/360).

-   **Generic OIDC** sign-in can be configured, tested and activated from **Admin** > **Auth / SSO**. It uses guarded provider discovery, PKCE, one-time sign-in transactions stored in the database, identity links scoped to the provider, and the same Cuttlely database session as the other methods. The public callback address must use HTTPS, except on `localhost`, `127.0.0.1` and `::1`. Email and its assurance come from one response: the ID token when it carries both (a qualifying `xms_edov` claim counts), otherwise UserInfo after its subject matches the ID token. **Test sign-in** passes only when ordinary sign-in would accept the returned identity, and activation stays unavailable until a test passes. Invitations and password acceptance follow the active method, and the Audit log shows OIDC outcomes, configuration fingerprints, issuers, subjects when present and the assurance basis. Generic OIDC sign-out returns straight to Cuttlely. [#359](https://github.com/cuttlely/cuttlely/pull/359).

-   **Owner recovery** is always available from the sign-in page for any active owner with a usable local password, whatever sign-in method is selected. It creates a normal Cuttlely session marked as recovery use, has stricter per-address and per-account throttling, and records every attempt as a high-severity audit event. A successful recovery writes a structured warning and shows an administrator alert until someone with **Authentication: Manage** acknowledges it; when SMTP is configured, owners also get a best-effort email. `CUTTLELY_LOCAL_ADMIN` is not needed for recovery; it still controls the older owner sign-in route. [#360](https://github.com/cuttlely/cuttlely/pull/360).

-   Harness Specialist can explicitly allow verified native read-only SQL when no tested pin covers a request, with the existing database guards and at most two such calls per specialist turn, and the optional **Interpret protected evidence** adds a labeled, source-grounded readout before the unchanged source facts. Both are off by default. See [Trusted outputs](./docs/reference/trusted-outputs.md). [#355](https://github.com/cuttlely/cuttlely/pull/355).

-   Trusted-output contracts can declare a monetary reporting symbol, so a readout can show a value such as `$1.25M` when the source has no currency code. An explicit source denomination wins, compact K/M/B values must match the rounding of the actual monetary source fields, and counts and percentages keep their source units. [#356](https://github.com/cuttlely/cuttlely/pull/356).

-   Markdown trusted-output contracts can opt in to private diagnostics for rejected numeric interpretation claims (`interpretationDiagnostics: true`). A separate author-only endpoint returns them and refuses API credentials; answers, traces and validation decisions are unchanged, and collection is off by default. [#357](https://github.com/cuttlely/cuttlely/pull/357).

### Changed

-   WorkOS, generic OIDC, Local login and owner recovery use the same Cuttlely database session and browser cookie. Every session request and every owned API credential request checks the user's current status, so disabling a user refuses their next call. A new API credential records the signed-in user as its owner, and one created through another API credential inherits that owner. Deactivating a person only in WorkOS does not end an existing Cuttlely session; disable the user in Cuttlely as well, or wait for the session to expire. [#360](https://github.com/cuttlely/cuttlely/pull/360).

-   Every sign-in method switch increments the authentication epoch and ends all interactive sessions. A staged switch is a single-use database record that expires after ten minutes and can be applied by another server process. Staging and applying each allow 10 requests per client address in 15 minutes, counted in each server process. [#352](https://github.com/cuttlely/cuttlely/pull/352), [#360](https://github.com/cuttlely/cuttlely/pull/360).

-   A WorkOS sign-in never counts as recent authentication for a method change: **Auth / SSO** sends a WorkOS administrator to **Owner recovery**, and while Local login is active **Sign in again** opens the local password form. A local password or owner recovery session counts for ten minutes, also while generic OIDC is active; an OIDC sign-in counts only with a qualifying `auth_time`. [#359](https://github.com/cuttlely/cuttlely/pull/359), [#360](https://github.com/cuttlely/cuttlely/pull/360).

-   **Auth / SSO** shows when the sign-in method last changed and how many sessions that change ended. A changed saved WorkOS client identity pauses automatic email and invitation linking until an administrator signs in again and acknowledges the warning; the acknowledgment ends interactive sessions, is recorded, and restores linking. [#360](https://github.com/cuttlely/cuttlely/pull/360).

-   Creating the first owner on a fresh owner-only installation, through browser setup or `pnpm user`, selects Local login in the same database transaction, so `/signin` shows the owner password form. A sign-in method that is already selected is left unchanged. [#360](https://github.com/cuttlely/cuttlely/pull/360).

-   API credentials cannot be created or updated with `authentication:` permissions, and the `/api/v1/authentication-settings` routes need a signed-in session. WorkOS sign-out deletes the Cuttlely session first, then ends the hosted AuthKit session, and goes to `/signin` if the hosted logout address cannot be created. [#360](https://github.com/cuttlely/cuttlely/pull/360).

### Fixed

-   Chatflow import, including the migration wizard, now refreshes nodes saved with no version or an older version to the current node, fills settings that have no saved value with their defaults, keeps each connection's edge reference in the node input it feeds, and lists connections that need attention. **Sync Nodes** runs the same steps and is now offered for nodes saved with no version. Agentflow v2 nodes are not changed. Flows imported with the migration wizard in 1.4.8 need a one-time repair: **Sync Nodes** where it is shown, otherwise exporting the flow and importing it again; see the upgrade notes. [#364](https://github.com/cuttlely/cuttlely/pull/364).

-   Chat model nodes no longer pass `NaN` as the temperature when the **Temperature** field is empty or is not a number. ChatOpenAI and 26 other chat model nodes now leave the temperature out in that case, so the model library's default applies; AWS ChatBedrock used `0.7` for an empty field before and now also leaves it out. [#363](https://github.com/cuttlely/cuttlely/pull/363).

-   Mixed harness answers keep separately requested documentation guidance next to a protected business report when the guidance comes from a separate documentation specialist that uses a Retriever Tool, has no MCP servers, shell, code execution, file access or protected-output contracts, and cites HTTP(S) source URLs its retriever returned in the same turn. Protected facts and files keep their existing validation and are not rewritten. See [Documentation alongside a protected report](./docs/reference/trusted-outputs.md#documentation-alongside-a-protected-report). [#365](https://github.com/cuttlely/cuttlely/pull/365).

-   Protected interpretation accepts written dates and date ranges with an explicit year, in English day-first or month-first form, when both endpoints appear in the source, and treats bold numbered Markdown markers as formatting. Unsupported amounts, percentages and counts are still checked. [#358](https://github.com/cuttlely/cuttlely/pull/358).

### Upgrade notes / breaking changes

-   **Flows imported with the migration wizard in 1.4.8.** Open each one. If the canvas shows **Sync Nodes**, click it. If it does not, the flow's nodes are already at their current versions and Sync Nodes is not offered; instead, select **Export Chatflow** in the canvas settings menu, then choose the import item in the same menu and select the exported file, or the original file you imported in 1.4.8. The migration wizard opens the result on the same canvas and rebuilds each connection's reference from its edge. It does not carry credentials or password, file and folder fields, so select the credential again on each node the wizard lists and fill those fields in again. In either case, then select **Save** and **Publish**, so Live serves the repaired version. Sync Nodes and the import change only the open canvas until you save, and a save goes to the draft, so a flow served only through the API or an embed stays broken until all steps are done.
-   **WorkOS installs: give an owner a local password.** From source, in the repository root, run `pnpm user --email <owner email>` with the email of the earliest active owner and enter a password at the prompt. With Docker Compose, run `docker compose exec -u node -it cuttlely pnpm user --email <owner email>`. With `CUTTLELY_LOCAL_ADMIN` off, the command accepts only the earliest active owner; to set the password of another existing owner, add `CUTTLELY_LOCAL_ADMIN=true` (with Docker Compose, `-e CUTTLELY_LOCAL_ADMIN=true` after `exec`). Until an active owner has a usable local password, administrators see a banner that owner recovery is not ready, and **Auth / SSO** refuses to activate WorkOS or generic OIDC. See [In a terminal](./docs/how-to/sign-in.md#in-a-terminal).
-   **WorkOS users sign in again once.** On the first start of 1.4.9, Cuttlely ends the older WorkOS browser sessions once, so those users sign in again one time. Local-user sessions and API credentials are unchanged.
-   **API credentials from before 1.4.9 have no recorded owner.** They keep working but are not tied to a user, so disabling a user does not refuse them. The API credentials list marks them for review or rotation.
-   **Empty chat model temperature.** A chat model node with an empty **Temperature** now uses the model library's default; on AWS ChatBedrock that replaces the earlier `0.7`. Enter a value to keep a fixed temperature.

## [1.4.8] - 2026-10-30

### Added

-   **Allow HTTP building blocks to call localhost** (`HTTP_ALLOW_LOCALHOST`) in **Admin** > **Server Settings** > **Security & network** > **Building blocks** lets HTTP building blocks, such as **HTTP** and **Execute Flow**, call `127.0.0.0/8`, `::1` and `localhost`. It is off by default and applies on the next request without a restart. When on, any flow author can reach any service listening on the server's own localhost. Private ranges, link-local and cloud metadata addresses, `0.0.0.0`, `::`, and every `HTTP_DENY_LIST` entry stay blocked. With `HTTP_SECURITY_CHECK=false` the switch changes nothing. See [Server settings](./docs/how-to/server-settings.md#let-http-building-blocks-call-localhost). [#350](https://github.com/cuttlely/cuttlely/pull/350).

-   **Maximum concurrent agent runs** (`CUTTLELY_HERMES_MAX_CONCURRENT_RUNS`) in **Admin** > **Server Settings** > **Agent runtime** > **Limits** sets how many agent runs the agent runtime works on at once. It defaults to `10` and accepts `1` to `50`, or `0` for unlimited; negative values and values above 50 are refused. It applies after a restart. The page warns about memory and CPU above 25, and more strongly for unlimited. See [Server settings](./docs/how-to/server-settings.md#maximum-concurrent-agent-runs). [#350](https://github.com/cuttlely/cuttlely/pull/350).

-   Optional per-specialist **Trusted outputs** bind a tested query hash to exact source Markdown fields, a verified monthly-utilization PNG or an exact source table CSV (up to 100 rows). The server uses the actual captured result and native attachment transport, replaces conflicting model output, preserves source section captions and reference blocks, and skips Harness Prime rewriting. Empty remains off; failures and unsupported sections are explicit. See [Trusted pinned-query outputs](./docs/reference/trusted-outputs.md).

-   Harness Specialist **Capacity wait (seconds)** can wait up to 60 seconds when the agent runtime rejects a new run because all concurrent-run slots are busy. It defaults to `0`, off, honors `Retry-After` and the turn budget, and does not rerun accepted turns or tools.

-   The PostgreSQL MCP pinned-query editor adds typed parameters, **Test & save** stamps, and best-effort audit entries for query changes and successful tests.

-   Agent Team lists have card and table views, model/tool/MCP icons, category chips and editing, sorting, and search by name or category.

-   **Agent run time** in **Admin** > **Server Settings** > **Agent runtime** configures specialist and nested-task waits. It defaults to four minutes; set 300 seconds for five minutes or `0` for unlimited, then restart. The whole-turn budget and cancellation still apply.

-   Harness Specialist **Pin first** can run one matching pinned query and render its answer before any specialist model call. Rule patterns match with a 50 ms limit per pass, and a pattern that runs longer is a miss. The option defaults to off.

-   Harness Specialist **Answer direct** can return an eligible single-step answer without a Harness Prime write-up. The option defaults to off.

### Changed

-   HTTP building blocks also refuse the unspecified IPv6 address `::`, like `0.0.0.0`, and a host name listed in `HTTP_DENY_LIST` is now refused by name as well as by the addresses it resolves to. [#350](https://github.com/cuttlely/cuttlely/pull/350).

-   Guarded PostgreSQL queries run faster with fewer database round trips and JIT disabled for catalog checks; user statements retain the login JIT setting.

-   The Harness Specialist **Handoff limit** tooltip now says what each value does: default 4,000, empty or `0` means the default, `-1` means no limit, and other values are kept from 160 to 20,000.

-   Analyst run traces add `sqlHash`, plus `sql` and `sqlTruncated` when `CUTTLELY_ANALYST_TRACE_PREVIEW` is on; SQL previews are redacted and capped at 4 KB.

-   The PostgreSQL MCP node's read-only query checks make fewer round trips: their own catalog reads no longer each open and release a savepoint, the allowed-function list resolves in one query, evaluating every entry in order even when no user function matches so lookup errors preserve legacy refusals, and the ACCESS SHARE locks on the selected tables and views go out in one round trip as LOCK TABLE lists over the same relations in the same order, with ONLY before every name so a listed table's inheritance children and partitions are not locked through it, and SELECT 1 FROM ONLY ... LIMIT 0 kept in place for a materialized view or foreign table. The remaining catalog reads are sent ahead in transaction-local batches and consumed once by the same JavaScript checks, in the same order; post-lock rechecks and the post-statement comparison stay in place. Queries with no routine calls still skip allowlist resolution, so a malformed signature does not cause a new refusal.

-   Analyst Postgres queries (a Postgres URL credential, `CUTTLELY_POSTGRES_URL`, the PostgreSQL MCP node and auto storage on Postgres) whose first page holds every row run their statement once instead of four times: the row count, the column type probe and the row length pass now run only when the first page is full or cut, and a result that pages is unchanged. Each transaction the query opens starts in one round trip, the PostgreSQL MCP node reuses its table selection summary for 30 seconds instead of opening a connection on every call, and the run trace's query step records per-step timings (`timings`), with the database's share (`dbMs`, every round trip to Postgres) apart from the connect (`connectMs`) and Cuttlely's own time (`cuttlelyMs`).

-   The UI HTML sanitizer uses dompurify 3.4.17. [#349](https://github.com/cuttlely/cuttlely/pull/349).

### Fixed

-   HTTP building blocks that call a host name, such as **HTTP**, **Execute Flow**, the API loader and the request tools, connect again on Node 20 and later. The connection still goes only to the address that was checked; it failed with `Invalid IP address: undefined` before. [#350](https://github.com/cuttlely/cuttlely/pull/350).

-   Publishing a specialist again with changed pinned-query parameters, under the same name, now gives the agent the new tool schema on its next start instead of the old one, and a changed connection no longer leaves that specialist without tools. Unchanged connections are reused, and public tool names stay the same. A tool call that is running while such a change is published can fail; it is not retried. [#351](https://github.com/cuttlely/cuttlely/pull/351).

-   Trusted PNG/CSV replay through a Harness card returns real in-memory previews without persistent storage or successful chat-download events. Compare remains text-only; normal delivery still requires storage success within the turn deadline.

-   Pinned and SQL fast-path answers no longer fall back to the slower handoff on long results that contain URLs or ellipses. Tool details are masked by one JSON-aware step in every event, the returned payload and the trace, so they stay valid JSON, including a string that is itself JSON. A string in a tool detail that still holds an absolute path after text masking, such as `a|/srv/x.csv`, is replaced as a whole; a URL keeps `,` and `;` in its query or fragment, and the workspace folder or a `file://` address after it is still replaced. A label such as `Q3..Q4` is no longer read as a path. Answer text keeps the existing masking. [#345](https://github.com/cuttlely/cuttlely/pull/345).

-   A HARNESS canvas id now works on the public `POST /api/v1/prediction/:id` route. It runs the Live (published) canvas, returns a `sessionToken` bound to the chat id, and needs the bound API key to list the harness. File uploads there are refused with 400; send them to a chatflow with a Harness card.

-   Guarded PostgreSQL queries, pins and `describe` samples work for a login whose role sets `default_transaction_read_only = on`. Validation opens a short read-write transaction only to create a temporary view, which is always rolled back; queries run in a read-only transaction. A read-only standby and a login without `TEMP` now get separate, plain messages instead of one shared one.

-   On a PostgreSQL MCP node that offers only pinned queries, a call by the node's own name no longer runs the first pin with the wrong arguments and pauses the tool; it returns an expected error naming the pins and their parameters. The analyst retry names the pins instead of the query tool, and a miss is logged as a `pinned query` step that says the analyst did not run a pinned query.

-   User Management can change an existing user's role: **Change role** on a row lists that person's teams and changes the role on one. The team role route now refuses a change to your own role (403; was 409), and a change to an organization owner's role by anyone who is not an organization owner. Someone who is not the organization owner can no longer change the role of, or remove from a team, a person whose team role has a permission they do not hold. `GET /api/v1/role` now also accepts `workspace:update`, so a team lead can load the role picker.

-   A harness specialist with the PostgreSQL MCP node that is not named `analyst` (its query tool is `mcp__<name>__query`) now gets its chat scope on every query call, so the run trace and the saved run keep that query step's row preview and `timings`, and its "show more" cursor stays with its chat.

-   Saving a shared draft now asks before it replaces a draft someone else saved after you opened the canvas. Reload shows their changes. Save anyway replaces them. Saving twice yourself does not ask, and an API save that sends no `expectedDraftHash` still replaces the draft.

-   Publish now checks the shared draft the same way a save does. If someone else saved the draft after you opened the canvas, Publish stops before anything goes live and offers to review their changes or publish their draft anyway. The publish route accepts `expectedDraftHash` and `overwriteDraftChanges`; a publish that sends no `expectedDraftHash` works as before.

-   When a save or a publish finds a draft someone else saved, a review screen now compares their draft with yours card by card and connection by connection. Changes that do not overlap merge on their own. Where you both changed the same card, connection, or setting, you see the changed fields side by side and pick yours or theirs. **Apply merge** puts the result on your canvas without saving it. Reload and Save anyway are still there.

### Upgrade notes / breaking changes

-   **Localhost access is off by default.** After the upgrade, HTTP building blocks still refuse `localhost`, `127.0.0.0/8` and `::1`. An owner can turn on **Allow HTTP building blocks to call localhost** in **Admin** > **Server Settings** > **Security & network**; the page marks it high risk, because any flow author can then reach any service on the server's own localhost. Entries in `HTTP_DENY_LIST` stay blocked either way.
-   **Concurrent agent runs apply after a restart.** **Maximum concurrent agent runs** defaults to `10`, the same limit the agent runtime used before. A saved change takes effect only after Cuttlely restarts.

## [1.4.3] - 2026-10-25

### Added

-   **Allowed functions** on the PostgreSQL MCP node lists your own SQL helpers, one `schema.fn(argtypes)` or `schema.fn(*)` per line. [How the selection is enforced](./docs/how-to/analyst.md#how-the-selection-is-enforced).

### Changed

-   While the startup profile compile runs, the harness gateway `GET /health` and `GET /api/v1/ping` return 503, and the start script waits for it. Once the wait cap passes, ping can return 200 while the compile is still running; chat and prediction stay at 503 until it finishes. `CUTTLELY_GATEWAY_STARTING_WAIT_SECONDS` defaults to 180 seconds and is capped at 300. [Agent runtime health](./docs/how-to/harnesses.md#agent-runtime-health).

### Fixed

-   1.4.3 compiles harness profiles from an older compiler again at startup, before the agent runtime reads them. `GET /api/v1/ping` answers 503 `boot recompile` while that pass is the startup gate, then 200. A profile that cannot be read or set aside is logged once and taken off the path the runtime loads. A link inside the profiles root is moved aside to a sibling `.quarantine` name; the target stays. A path outside that root is refused and left in place, never quarantined. A file already at that name is left unchanged. If every suffix is taken, or the move fails, that path is logged once and the profile stays failed. Warm-up holds the profile lock only while it compiles, then waits for the runtime. The rest of the service still comes up. The start script waits at most 300 seconds.
-   A lone Harness card on an agent keeps `harness`, so existing flows that call `tool:harness` still run. When two or more Harness cards are on one agent, each gets its own tool name with a unique suffix.
-   The Current Date Time tool can format the local date and time in an IANA timezone. Set **Timezone** on the node, or `CUTTLELY_DEFAULT_TIMEZONE` when that field is empty. JSON, code, password, file, and folder inputs, header inputs, inputs the node does not declare, and credential references are left out. A canvas link is kept only when the value is exactly `{{nodeId.data.instance}}` for a node id of the form `name_0` that is present in the same flow. Any other value on that link is left out. Label, description, category, tags, input parameters, input anchors, output anchors, and output values are rebuilt from the node's registered component, including the anchor ids the canvas uses. The node itself keeps an id of the form `name_0`, a type of `customNode`, `stickyNote`, `agentFlow`, or `iteration`, a position made of two finite numbers, and a finite width and height. Style, extent, a parent node, absolute position, and every other field are left out. A value that is not an object is left out and recorded. Each connection is rebuilt as id, source, target, source handle, target handle, and type. It is kept only when both nodes were kept, the source handle is an output anchor id of the source, and the target handle is an input anchor or input parameter id of the target. The id and the type must be plain strings with no token-shaped prefix; the type is `buttonedge` or `agentFlow`. A saved chain still has its connections after the template is loaded, including the chat model link. A node whose component is not registered keeps no saved metadata and is included in the record of nodes that lost settings, with the node id as its label. The template records each node that lost a setting (node id, label, and input names). A saved custom tool template keeps func when the token-prefix, high-entropy, and decoding checks pass. An address, `//`, `@`, or a scheme-like word in func does not by itself leave func out. Func is left out whole when it has an address with a password in its user info, a query parameter named `api_key`, `apikey`, `key`, `token`, `access_token`, `secret`, `password` or `sig` (any case, any value), or `Bearer` or `Basic` followed by a literal value; an ALL_CAPS placeholder name such as `SPIDER_API_KEY` after `Bearer` is kept. These func checks run on the raw text, the decoded text, and both with invisible characters removed or turned into spaces, and a password in user info is found after `//` with or without a scheme, when any `:` comes before the last `@` of the address. `Bearer` and `Basic` match in any ASCII letter case, after any character other than an ASCII letter, digit or underscore, with invisible characters inside the word, and with any mix of whitespace, invisible characters and `\n`, `\t`, `\r`, `\v` or `\f` escapes between the word and the value. The address scan starts after `//` or after the colon of `http`, `https`, `ws`, `wss` or `ftp` (skipping any run of slashes or backslashes, or none), and runs until `/`, `?` or `#`, so quotes, spaces and line breaks inside user info are read too. These func checks also run with all whitespace removed, and with `\n`, `\t`, `\r`, `\v` and `\f` escapes removed. In func, a slash ends a high-entropy run, so a path is not one run. Schema still uses the full text check, including those address patterns, and is left out whole when it matches. A JSON schema is saved as the checked value written out again, not as the submitted text. Its icon address is rebuilt with the same http and https rules as an avatar (scheme, host, and path, with the path-segment and host-label checks) and is left out when the rebuild fails. The template records the name of each of those fields that was left out. The template preview and the canvas after import show which nodes need those settings entered again, with the note: connection settings are not included in templates; re-enter them after import. Prompt text is kept as written, so do not put credentials in prompts. A prediction whose credential is missing answers 422 without the credential id, including when a harness reports it.
-   The first-run setup code is stored as an HMAC with the time it was issued, when it expires, and when it was used. Creating the first account and exchanging the code both require that code and the `x-request-from: internal` header, including a request from this machine. [Invite people](./docs/how-to/sign-in.md#invite-people).
-   A raw MCP server listed in a specialist record's `mcpServers` now passes the same checks as a Custom MCP node (`CUSTOM_MCP_ALLOWED_COMMANDS`, `CUSTOM_MCP_ALLOWED_ABSOLUTE_SCRIPT_PATHS`, `CUSTOM_MCP_ALLOWED_ENV_VARS`, no `cwd`, no shell characters, no code-running flags) before the agent runtime starts it. One that fails is left out of the profile with a warning in the server log. `CUSTOM_MCP_SECURITY_CHECK=false` turns the checks off, as it does for the node.

### Upgrade notes / breaking changes

-   **API keys need their harnesses ticked.** An API key that calls `POST /api/v1/harnesses/:name/runs`, reads that harness's runs, or reads, saves or deletes the harness by name, now also needs the harness under **Harnesses this key may run**, and gets `403` `This API key may not run harness "<name>".` otherwise. Before, the role permission was enough. The same goes for a chatflow or agentflow bound to a key whose Harness card or Agent harness tool names a harness: that card fails until the harness is ticked on the flow's key. After upgrading, edit each such key and tick its harnesses. At startup the server logs each bound key that is missing a harness its flow names.
-   **Known limits of the harness list.** A flow with no API key still runs every harness it names, in its team, for anyone who has its id. Execute Flow, Chatflow Tool and Agent as Tool send the API key stored in their credential, so the flow they call runs under that key's list, whoever can use the credential: keep keys that list harnesses out of shared credentials. [Known limits](./docs/api.md#known-limits).
-   **Flow config needs a permission.** `GET /api/v1/flow-config/:id` now needs `chatflows:view`, `chatflows:update`, `agentflows:view` or `agentflows:update`; before, it checked none.
-   **Draft chat refuses API keys.** `POST /api/v1/internal-prediction` now answers `401` to every API key. An app uses `POST /api/v1/prediction/:id`.
-   **Database changes for harnesses.** At startup the app database adds a `harnesses` column to the API key table (migration `AddApiKeyHarnesses`), empty on every existing key, and the harness database adds a `harness_schedules` table.
-   **API keys are no longer accepted in a URL.** `GET /api/v1/chatflows/apikey/<key>` and `GET /api/v1/verify/apikey/<key>` now answer 400 without checking the key. Send the key as `Authorization: Bearer <key>` to `GET /api/v1/chatflows/apikey` or `GET /api/v1/verify/apikey` instead. A client or script that still puts the key in the path breaks until it is changed. Once it is, consider rotating any key that was sent in a URL, because proxy and access logs may still hold it.
-   **Rate limits on sign-in and a few other routes.** Sign-in, the API-key check, OAuth credentials, custom MCP servers, and node and credential icons now answer 429 past **Page loads a minute** (`CUTTLELY_UI_PAGE_LIMIT_MAX`, 3000 by default) per client address. Behind a reverse proxy, set `TRUST_PROXY` before you upgrade, or every client shares one count and sign-in can be blocked for everyone. [Server settings](./docs/how-to/server-settings.md).
-   **Raw MCP servers on specialist records.** A raw entry in a specialist's `mcpServers` (one that is not an MCP node connected on the canvas) now starts only if its command is in `CUSTOM_MCP_ALLOWED_COMMANDS` and its script path is in `CUSTOM_MCP_ALLOWED_ABSOLUTE_SCRIPT_PATHS`. Both are empty by default, so every such server is refused until you set them. A refused server is left out of the harness, and the server log has a warning that names it. If `packages/components` is not built, every raw server is refused. Before you upgrade, set those allow-lists (and `CUSTOM_MCP_ALLOWED_ENV_VARS` for any `env` the server passes), or set `CUSTOM_MCP_SECURITY_CHECK=false` to keep the old behavior.
-   **Pending invites need their invite link.** An invited person now joins only through their own one-time invite link: it is single use, expires (72 hours by default), works only for that person and the email it was sent to, and stops working when a newer link replaces it or the person is disabled or removed from the team or the organization. A sign-in whose email matches a pending invite never activates it, even with a verified email, and shows `You have a pending invite. Open the invite link from your email to join.` An invite link issued before the upgrade keeps working until it expires: without AuthKit it still sets a password, and with AuthKit on it is used through **Accept invite with WorkOS**, not a password. A user already stored as `invited` before the upgrade can use such a link; otherwise make one with `POST /api/v1/users/:id/reset-link` and send it. A person added with **Add User** before the upgrade was stored as `active`, not pending, and can still join by email match; to require the link, remove them and invite them again. With AuthKit on, every new invite returns or emails a link, and **Add User** shows it once. [Upgrading](./docs/upgrading.md#invites-after-130).
-   **Database changes.** At startup the ETL database moves to schema version 4 and gains a `run_names` table, which records the pipeline name each run ran under. Each run that started before the upgrade is recorded under the pipeline's name at upgrade time. Vectors written under a name the pipeline had before it was renamed, before the upgrade, are not removed when the pipeline is deleted.

## [1.0.0] - 2026-10-10

The first Cuttlely release. It covers everything on `main` up to the release tag.

Cuttlely is the open-source agent platform for applications: build an agent team on a canvas or from a description, chat with it in minutes, and call it from your app through the API. The README and docs lead with that, with a real API call to a small team and the chat-first path for newcomers.

### Harnesses

-   Build agent teams on the harness canvas. Harness Prime reads the question, routes each part to a specialist using a short summary of each one, and writes one answer. A chatflow calls the whole team by name.
-   Specialists run in the agent runtime that ships with Cuttlely and starts with it on the same server. Each turn starts a fresh session, and follow-up questions still work. Specialists get their tools directly, load playbooks only when needed, and their instructions name each playbook.
-   Harness Prime reads up to 4,000 characters of each specialist answer, and it sees images attached to the turn. Images a specialist writes during a turn show up in the chat.
-   A step can wait for an earlier step and use its result.
-   The run card shows the route, each specialist, and the tokens in and out. Specialist tokens count toward the turn total, and cached prompt tokens are shown separately.
-   Build with AI on the harness canvas: describe your team and a first version lands on the canvas.
-   **Try the demo** on a new install: pick or add one model key, and a ready-made bakery team (made-up sales data and a made-up handbook) opens with its chat open and three starter questions. The first one answers with a chart.
-   Charts and other images a team makes also show up in the harness canvas chat.
-   A question asked while the agent runtime is still starting waits for it, up to a minute (`CUTTLELY_HERMES_START_WAIT_MS`), instead of failing with "Hermes did not accept POST /v1/runs".
-   Harness templates open on your own model key: the sample xAI Grok card becomes the chat model you have a key for, or keeps xAI with your key filled in. A model card with no key picked picks your key when exactly one fits.

### Analyst

-   A specialist with its own database. It creates tables, adds rows and answers questions about them, and it never reads Cuttlely's own tables. Turn it on with `CUTTLELY_ANALYST=auto`. The analyst database is kept apart from the application database, including on Render.
-   Long results come back in pages ("show more"). The run card keeps every row a query returned, behind the query chip.
-   A read-only analyst fixes a failed SQL statement once by itself. The SQL dialect follows the PostgreSQL credential on its card.
-   A 15-second statement timeout applies to every analyst call, on Postgres and on SQLite.

### ETL pipelines

-   Pipelines load files, a CSV or a code repository, then clean, split, embed and store the data for search. A run embeds only what changed and can run on a schedule. Local embeddings need no provider key.
-   Harnesses and chatflows search a pipeline's output with the **ETL Retriever**.
-   Deleting a pipeline also deletes the vectors it wrote.
-   Build with AI on the ETL canvas: describe your data and a first pipeline lands on the canvas.

### Chatflows and agentflows

-   The new card look is the default: compact cards, with settings in a side panel. People can choose **Classic cards** for themselves, and `CANVAS_CARD_LOOK=classic` sets classic as the server default.
-   Typing in a card field or a document loader field keeps your cursor where it was.
-   Every bundled template opens cleanly. Nine templates whose cards overlapped were respaced.
-   Opening a canvas fits every card in view.
-   Older V1 agentflows are hidden from the app and keep running. New agentflows use the current workflow canvas.
-   The xAI Grok card's **Model** field is a list of current Grok models, starting at `grok-4.7`. Any other model name your xAI account offers can also be typed in, and model fields that allow typing keep what you typed.
-   Model lists are current as of October 9, 2026, for every chat model, LLM and embedding card that has one: new models and prices, models the provider has shut down removed, and current defaults on new cards (for example `gpt-5.6-luna` on OpenAI, `claude-haiku-5-5` on Anthropic, `gemini-3.8-flash` on Google Gemini and Vertex AI, `deepseek-flash` on DeepSeek, `mistral-small-latest` on Mistral, `voyage-4` on Voyage AI and `text-embedding-3-small` on OpenAI embeddings).
-   OpenRouter, Fireworks, Together AI, SambaNova, NVIDIA NIM, IBM watsonx, Alibaba Tongyi and CometAPI cards offer a **Model** list of popular current models. Every model list also takes a typed model name, so a flow saved with a model that has left the list still opens and runs with it. Cards for servers you run yourself, such as Ollama, LocalAI, LiteLLM and OpenAI Custom, keep a plain text field.
-   Claude Sonnet, Haiku, Fable and Mythos 5 and later get no temperature, top P or top K, which those models refuse, and the Anthropic card offers adaptive thinking and effort on the Claude 5 models. GPT-6 models are treated as reasoning models on the OpenAI and Azure OpenAI cards.
-   Bring flows from other tools with a checked import wizard, from the **Import** menu on Chatflows. See [Bring your existing flows](./docs/bring-your-flows.md).
-   **Deprecated:** the OpenAI, Azure OpenAI and Cohere LLM (text completion) cards no longer appear in the node list for new flows, not even when searched by name, because those providers no longer offer a completion model. Flows that already use one still open and run as before. For new flows, use the chat model card of the same provider. Other deprecated cards show again when you search their exact name.

### Build with AI

-   On the chatflow, harness, ETL and workflow canvases, describe what you want and a first version lands on the canvas. Every part and connection is checked first, problems get one repair round, and credentials are matched by name. The building model is one of your own credentials.
-   Build with AI starts on a model you have a key for, with your key picked when only one fits. The list shows models for your keys first, and advanced settings wait under **More settings**.

### Versioning, Publish and Dev to Prod

-   Version history is on by default. Each save records what changed and who changed it, with diff colors and secret-looking text hidden. Restore a version, or open it as your draft. `CUTTLELY_VERSIONS=off` turns history off.
-   Drafts are on by default for chatflows and agentflows. The canvas saves to a draft. The API, embeds, shared links, schedules and webhooks keep serving Live until you publish. History shows Published markers and offers **Roll back Live**. `CUTTLELY_DRAFTS=off` turns drafts off.
-   The Publish check runs up to 10 recent questions on Live and on the draft and shows the answers side by side, with the tokens and time each took. It works on chatflows and on agentflows that start with a chat message.
-   Keep a copy of every version in a GitHub repository, from Admin, Version History. First-run setup goes straight into the app; it does not stop at a GitHub page.
-   Dev to Prod: Prod reads what Dev published, shows what would change and which credentials it needs, can run the same check, and goes Live only when its owner selects **Promote to Live**.

### Install and operations

-   A published Docker image, `ghcr.io/cuttlely/cuttlely:X.Y.Z` and `:latest`. Compose pulls it by default and builds your checkout when it cannot pull. The image reports its health from `/api/v1/ping`.
-   `npx cuttlely` starts that image. The `cuttlely` package is a Docker launcher, and `@cuttlely/chat` is the embeddable chat widget. The server stays in the image.
-   The Docker image runs on Debian trixie with Node 24. It runs as the `node` user and keeps its data in `/var/cuttlely`. Compose passes `CUTTLELY_VERSIONS`, `CUTTLELY_DRAFTS` and `CUTTLELY_ANALYST` from `.env`.
-   A Render Blueprint runs one container with Postgres.
-   From source on Node 24 with pnpm.
-   Sign in with a local account, or with WorkOS AuthKit for a team. On a fresh install the server log prints a one-time setup link, so the first account can be created in the browser, including through Docker's published port.
-   One process and SQLite by default. Harness turns use a SQLite queue in the web process.
-   **Server settings, Restart**: a full-screen view follows the restart (saved, runs finishing, stopping, each start-up step, back). When chats or agent team runs are in progress, Restart asks whether to let them finish (up to the turn time limit) or restart now; new runs wait meanwhile. The manual restart steps have a copy button.
-   **Server settings, safe boot**: a start that can't open the database after a settings change stops (exit 76) instead of running half-started, the start script starts it again, and its settings never become the last good copy, so the third start puts back the settings that worked. The restart screen shows that outcome as **The new settings did not start**. `pnpm verify` checks it on the real server (`pnpm safeboot:check`). When the start script (Docker, Render, a source install) does the rollback, it now tells the server, so the safe boot banner and that restart screen outcome show there too.
-   **Server settings guide** ([docs/how-to/server-settings.md](./docs/how-to/server-settings.md)) with real screenshots. Polish: high-risk changes need RESTART typed in the review; the safe boot banner has See what changed and Try it again; All settings has Copy as .env (secrets left out); queue mode reminds you to restart the workers; Switch database warns about the encryption key for a database that already holds Cuttlely data. On a phone the sections sit in one sideways row and the save bar fits; dialog buttons are in sentence case; setting names and the search field read clearly in dark mode. The page always keeps room for the save bar: it scrolls fully clear of it, and a field you move to never ends up under it. The sidebar marks the page you are on, also when you open it from an address, a link or the back button, including the pages under Admin.
-   **A one-time setup link when nobody can sign in**: a server with no account, the password sign-in off and no AuthKit (for example Render without the WorkOS values) prints a link in its log that opens only Sign-in & identity. Create the owner with a password, or set up AuthKit after a test sign-in with the owner email. The link works once and stops working once the first account exists. When accounts exist but no sign-in method is on, the browser shows the Sign In page with Sign-in is not configured instead of an empty page, and the log says how to turn one back on.
-   **Health check knows about the database**: while Cuttlely can't reach its database, at startup or later, `GET /api/v1/ping` answers `503` with a plain reason (for example `database unreachable: connection refused`), so Docker shows the container unhealthy and Render keeps a deploy without its database from going live. The log has one line naming the host and port, never the password, and Cuttlely never says it is ready without its database. Ping answers `pong` again once the database does.
-   **Server settings, Set up your server**: three optional first steps at the top of Server settings (sign-in for your team, the analyst, a model key), each opening the same section. Skip for now hides them.
-   **Server settings, Switch database**: SQLite or Postgres from the Database section. The new database is always tested first (sign-in, can create tables, empty or Cuttlely data already, other tables refused), the dialog says how the owner gets back in afterwards, the switch needs RESTART typed, and the previous database is kept for Switch back. Data is not copied.
-   **Server settings, Set up AuthKit**: a four-step guide in Sign-in (WorkOS key and Client ID with Staging or Production detected from the key, redirect addresses filled in with copy buttons, Generate seal, first owner email), then a real test sign-in with the values on screen, bound to the owner's browser session, before anything is saved. Password sign-in cannot be turned off until a test sign-in with the exact AuthKit values passes.
-   **Server settings, Test connection**: Analyst, File storage and Models each have a Test connection card that tries the values on the page before you save (Postgres sign-in and read-only check; S3, Google Cloud or Azure find, write and remove a small test file; the model list is fetched and checked). Errors come back in plain words, never with a secret in them.
-   **Admin, Server settings** (owner only): sign-in, database, agent runtime, analyst, models, storage, security, integrations and advanced settings in one page, with search, plain-language help, a review step before saving, Locked for values set where Cuttlely is installed, All settings, and History. Secrets are write-only. Changes apply at the next restart.
-   `scripts/start-cuttlely.sh` restarts the server in place when it exits with code 75, which is how Server settings applies a change. Safe boot puts back the last settings that started after two starts in a row that did not finish, and `pnpm settings list|unset NAME|restore` is the way back in from a terminal. [Upgrading Cuttlely](./docs/upgrading.md) has the details.
-   `pnpm verify` is the local merge gate.
-   Upgrades are tested. The full `pnpm verify` starts the current server on data written by an older Cuttlely and checks that flows, version history, credentials and harnesses survive (`pnpm upgrade:check`). [Upgrading Cuttlely](./docs/upgrading.md) covers backup, upgrade and roll back.
-   Model dropdowns and prices come from a model list the Cuttlely maintainers keep in this repository. A server fetches it from `main` at most once a day (5 second timeout) and uses the copy bundled with its build when that fails. `MODEL_LIST_CONFIG_JSON=bundled` turns the fetch off; a file path or URL replaces the list.
-   A quieter first start: the agent runtime skips about ten "Nous Portal not configured (run: hermes auth)" warnings, since Cuttlely never uses Nous Portal. Set `CUTTLELY_HERMES_NOUS_WARNINGS=show` to see them.
-   Start-up never looks stuck: the image build names each long step (1 of 4 to 4 of 4), the start script and server log each boot step, the log ends with `✅ Cuttlely is ready. Open http://localhost:43117`, and a browser opened during boot gets a **Cuttlely is starting** page that opens Cuttlely when it is ready. Ping answers `503` with `"status":"starting"` until then, so the Compose health check reads `health: starting`, then `healthy`. `CUTTLELY_STARTING_PAGE=off` turns the page off.
-   **Graceful shutdown**: on SIGTERM or SIGINT (what Docker and Render send on every stop and deploy), Cuttlely stops taking new requests, which get `503` with `Retry-After` (ping too), and lets running answers and streams finish for up to 25 seconds (`CUTTLELY_DRAIN_TIMEOUT_MS`). A run still going after that gets a `503`, or an `error` event with status `503` and code `UNAVAILABLE` on a stream, instead of a cut connection. A second signal stops at once. The Compose files give the container 35 seconds to stop.

### Security and API

-   The agent runtime makes no request to models.dev unless `CUTTLELY_MODELS_DEV=1` is set. `SECURITY.md` lists every host Cuttlely connects to and how to turn each off.
-   The API-key chatflow list returns only the flows bound to that key, and only their `id`, `name`, `deployed`, `category` and `type`.
-   Refreshing an OAuth credential needs a session or an API key with credential permissions.
-   Server settings (`/api/v1/server-settings`) are for the owner's signed-in session only. API keys are refused, secret values are accepted but never returned or logged (request bodies stay out of debug logs), and every save, discard and restart goes into the settings history.
-   Prediction errors keep their real status. A streamed `error` event carries `status` and `code`.
-   A model provider that keeps answering 429 is reported as `429` with `Retry-After` (the provider's wait when it sends one, otherwise 30 seconds), not as `500`, and within about 20 seconds instead of about 95: chat models and LLMs make at most 3 tries and start no new try after 20 seconds. A one-off 429 still recovers on the next try. A streamed `error` event also carries `retryAfter`.
-   A prediction with `Origin: null`, or an Origin that is not a URL, is refused.
-   Override configuration never takes a port from a request.
-   A request value never runs as code. In Multi-Agent and Sequential Agent flows, an allowlisted variable referenced in a code input is inserted as escaped text, so it reads as the same text inside quotes and cannot become code anywhere else (covered by tests, including an injection attempt).
-   Dependencies are on patched releases: `pnpm audit` reports no critical advisory and three high ones, none with a fixed release (two in Puppeteer's browser download, which Cuttlely skips, and `braces` in the command-line file matcher and in dev tooling). `expr-eval` is not installed: the older community package that depended on it is gone, and that package has no fixed release. The UI no longer installs Create React App (every UI script already runs Vite), and the server no longer installs a mail library it never used. Excel files are read with SheetJS 0.20.3, the fixed release SheetJS publishes on its own download site. The UI, agentflow and observe builds run on Vite 6.
-   The Docker image is built in two stages: the image you run has production packages only and no compilers.
-   Prediction uploads stay per chat. An image, audio or other file sent again with the same name, in the same chat or another one, is stored under a new name and never replaces an earlier file. Deleting a chat also removes the documents it sent, not only its folder.
-   Deleting a flow also deletes its leads (the name, email and phone people left in its chat), in the same step as the flow, its messages, feedback and upsert history. If any part fails, nothing is deleted.
-   Override configuration never takes the Agent card's knowledge lists (`agentKnowledgeDocumentStores`, `agentKnowledgeVSEmbeddings`) from a request, nor any list whose items choose an embeddings, vector store or model card. A request could otherwise add a knowledge item with no saved credential, which some providers run on a key from the server's environment.
-   Override configuration never switches the model, embeddings or vector store card a step uses (`agentModel`, `llmModel`, `conditionAgentModel`, `humanInputModel`, `embeddingModel`, `vectorStore`, and any picker that loads a card's settings). The saved credential belongs to the owner's card, and another provider could fall back to a key in the server's environment. Settings on the owner's card, such as `modelName` and `temperature` in `agentModelConfig`, still apply when allowlisted.
-   File names stored with a flow can never read outside that flow's folder (covered by tests).
-   Prediction uploads follow the flow's upload settings on the server, not only in the chat. An image, recording, document or chat file the flow does not accept is refused before anything is stored: 403 when that kind of upload is off, 400 for a file type the flow does not take. The chat, the shared chat and the embed upload as before when uploads are on.
-   A file link in an Agent's answer is signed and opens for 15 minutes without the flow's API key, for that one file in that conversation of that flow. Before, a browser user of a key-protected flow got 401 from the link. A changed or expired link is refused, and the key and session checks are unchanged.

### Good to know

Back up your data directory, including its encryption key, before any upgrade. [Upgrading Cuttlely](./docs/upgrading.md) has the steps and how to roll back.

-   **Status codes.**
    -   A prediction with `Origin: null` (sandboxed iframes, `file://` pages) or an Origin that is not a URL gets 403. Server-to-server calls without an Origin are accepted.
    -   Uploading an attachment when uploads are off for the flow returns 403. A file type the flow does not allow returns 400.
    -   A harness that cannot run returns 422 `CANNOT_RUN`. Other 4xx errors keep their status: 402 `QUOTA_EXCEEDED`, 403 `FORBIDDEN`, 404 `NOT_FOUND`, 429 `RATE_LIMITED`. Anything else is 500 `INTERNAL_ERROR`.
    -   An OAuth credential refresh that the provider rejects with 401 returns 502.
-   **Streaming rule.** `/api/v1/prediction` and the canvas test chat route (`/api/v1/internal-prediction`) stream only for `streaming: true` or `streaming: "true"`. Values like `1`, `"1"` or `"TRUE"` get a JSON answer.
-   **Port overrides.** `port`, `*_port` and `*Port` settings are never taken from a request, even when allowlisted. Leave port entries out of your override configuration, and remove any that are already there. See [Override configuration](./docs/reference/override-config.md).
-   **Stream error events.** A streamed `error` event keeps the message in `data` and adds `status` and `code`.
-   **Image path.** The image's working directory is `/usr/src/cuttlely` (was `/usr/src/flowise`). Update any volume, script or shell command that used the old path. The data volume (`/var/cuttlely`) is not affected.
-   **Prediction uploads.** `POST /api/v1/prediction/:id` takes only the uploads the flow accepts. Documents sent in `files` or as uploads need file uploads on (**Configuration**, **File Upload**, **Enable Full File Upload**), images need a card with image uploads on, and audio needs Speech to Text. Others get 403 when that kind is off, or 400 for a type the flow does not take, and nothing is stored. A file for a document loader input allowed in Override Config is still taken. See [Send a file with the question](./docs/api.md#send-a-file-with-the-question).
-   **Knowledge list overrides.** `agentKnowledgeDocumentStores` and `agentKnowledgeVSEmbeddings` are never taken from a request, even when allowlisted. Remove them from your override configuration; the knowledge saved on the Agent card is used. See [Override configuration](./docs/reference/override-config.md).
-   **Card picker overrides.** `agentModel`, `llmModel`, `conditionAgentModel`, `humanInputModel`, `embeddingModel` and `vectorStore` are never taken from a request, even when allowlisted. Allowlist settings on the card instead (for example `modelName` in `agentModelConfig`). See [Override configuration](./docs/reference/override-config.md).
-   **Request variables.** Request `vars` reach `{{$vars}}` only in Multi-Agent and Sequential Agent flows. In chatflows and agentflows they reach code that reads variables, not `{{$vars}}` in a card's text. In Multi-Agent and Sequential Agent code inputs, a request value written as `{{$vars.name}}` is now inserted as escaped text: inside quotes it reads as before, outside quotes anything but a number stops that card's code with a syntax error. Read `$vars.name` in code instead. See [Request values in code inputs](./docs/reference/override-config.md#request-values-in-code-inputs).
-   **API-key chatflow list.** `GET /api/v1/chatflows/apikey/:apikey` lists only flows bound to that key, with five fields. An unknown key gets 401.
-   **OAuth refresh.** `POST /api/v1/oauth2-credential/refresh/:credentialId` needs a session or an API key with `credentials:create` or `credentials:update`. A credential in another workspace gets 404.
-   **Drafts on by default.** A canvas save starts a draft, and **Publish** makes it Live. Scripts that call `PUT /api/v1/chatflows/:id` write Live. `CUTTLELY_DRAFTS=off` makes the canvas save straight to Live.
-   **Version history on by default.** It needs `git` on `PATH`; the image includes it. `CUTTLELY_VERSIONS=off` turns it off.
-   **Model lists.** Models their providers have shut down, or shut down before November 2026, are not offered, among them `gpt-3.5-turbo`, `gpt-4`, `o1`, Claude 3 models, Gemini 1.5 and 2.0, `deepseek-chat`, `mistral-tiny` and Cohere v2 embeddings. A flow saved with one keeps that model name and still sends it, so it works for as long as the provider accepts it; pick a current model on the card to move off it.
-   **Card look.** The new card look is the default. `CANVAS_CARD_LOOK=classic` sets classic cards for everyone who has not chosen.
-   **V1 agentflows.** Existing V1 agentflows run and open from a direct link. You can't create, duplicate or save one as a template.
-   **Local account on by default.** `scripts/start-cuttlely.sh` turns the local password account on (`CUTTLELY_LOCAL_ADMIN=true`) unless you set it; a blank value counts as unset. In Docker it stays on even with WorkOS keys (Compose sets `CUTTLELY_INSTALL=docker`). From source, the start script leaves it off when `WORKOS_API_KEY` is set or `packages/server/.env` sets it. On Render it is left off. Set `CUTTLELY_LOCAL_ADMIN=false` in `.env` to keep it off.
-   **Node 24.** Running from source needs Node 24 (`.nvmrc`).
-   **Data directory.** Data lives in `~/.cuttlely`, or `/var/cuttlely/data` in Docker and on Render. Keep the encryption key with the database.
